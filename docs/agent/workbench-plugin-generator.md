## §1 架构地图

```
agents/*.md              六个 agent 定义（front matter = 运行参数，正文 = system prompt）
agents/_common.md        公共守则，拼在每个 system prompt 前面
agents/<id>.lessons.md   这个角色攒下来的经验（和定义分开放，见 §4.12）
flows/*.flow.json        流程模板（可复用，不归属任何项目）
projects/*.project.json  开发项目：一个仓库目录 + 它选用的流程
packages/shared/         三方共用契约：类型、renderPrompt、topoSort、五种插件生成器
apps/server/             Fastify + CLI 适配 + 拓扑调度 + SSE
apps/web/                React Flow 画布 + 对话式创建
runs/ conversations/     运行记录与会话（都不进 git）
traces/ evidence/ cases/  全过程记录、内容寻址证据库、案例库（都不进 git，见 §7）
```

**四条边界，越界就会出事**：

1. **`packages/shared/src/index.ts` 是单一契约来源。** 界面、服务端、磁盘上的 flow JSON 三方共用。改结构语义要同时把 `FLOW_VERSION` 加一，`flows.ts` 拒绝加载版本不匹配的文件——**尽力而为地猜比报错难查得多**。
2. **判据只在服务端算数。** 界面置灰是提醒，挡不住 curl 和别的会话。
3. **判据必须在花钱之前。** 见 §4.1。
4. **服务端不做沙箱。** 权限边界完全交给 CLI 的 `--permission-mode` / `--allowedTools`（claude）或 `-s`（codex），以及节点上填的工作目录。加功能时不要绕过这两个参数直接执行东西。

**三层持久化**（2026-09-04 收敛，见 §4.2）：磁盘上十种文档全部走 `apps/server/src/docstore.ts`——版本化、运行时校验、原子写、坏文件保原样。

**对话式创建那一层**（2026-09-04 起）分工是死的：

| 谁 | 负责 |
|---|---|
| `packages/shared/src/nextstep.ts`（纯函数） | **判定**：现在哪一阶段、还缺什么、允许做什么、能不能下载 |
| `apps/server/src/guide.ts` | **理解和解释**：把大白话变成字段、把缺项讲成人话 |
| `apps/server/src/chatactions.ts` | 能写哪些字段、风险分级、冲突检测、撤销 |
| `apps/server/src/prepare.ts` | 从一个起跑请求到调度器转起来，**所有花钱之前的判据都在这** |

**评估与数据那一层**（2026-09-09 起，见 §7）同样是「纯逻辑判定 + 适配边界」的分法：

| 谁 | 负责 |
|---|---|

## §2 落地清单（新主机从零跑起来）

1. Node ≥ 20 + pnpm；`pnpm install`。
2. `pnpm dev` 起两个进程：服务端 `127.0.0.1:5178`、界面 `localhost:5177`。
   ⚠ vite 在有些机器上**只绑 `localhost`**，`127.0.0.1` 连不上——顶栏连不上服务端时先换这个地址试。
3. 装好 `claude` 或 `codex` CLI 并登录。右上角徽章会去问 CLI 要版本号——**顶栏显示出版本号才算通**，「服务端起来了」证明不了流程能跑。
4. 现场机器有一键脚本：`安装环境.cmd` / `启动.cmd`（`tools/launch/`）。
   ⚠ 这两个 `.cmd` **整份必须是纯 ASCII**（含它引用的路径）——cmd 按控制台代码页解析字节，非 ASCII 在别的代码页机器上连路径都会变乱码。
5. 要生成插件还需要：宿主的**插件开发包**（在 HuikeAgent 那边跑「导出开发包」，再在「接口规则」页导入）、以及 `dotnet`。
   ⚠ **宿主升级之后第一件事是重新导入开发包**——契约面变了而工作台不知道，生成出来的代码引用的成员可能已经不在了。

**三样有意不进 git**：`runs/`（运行记录）、`conversations/`（会话）、`rules/<id>/`（导进来的别人的代码，能一键重导）。

**验证**：

```
pnpm verify      # 三包 typecheck + 764 条用例 + web build
pnpm ui:smoke    # 10 份浏览器验收（改界面时必跑）
```

⚠ **typecheck 通过不算验证完**。改动跟运行链路有关时，起服务端真跑一遍看到 `RUN.END done` 才算；插件生成那几份验收（`plugin` / `cameraplugin` / `commplugin` / `flowplugin` / `diagplugin`）**真的跑 dotnet**，几分钟一轮别嫌慢——「`ResourceUri` 没有 `Parse`」「`ParameterDescriptor` 在哪个命名空间」这类错 typecheck 一个都拦不住。

## §3 这套东西解决的问题与选型

**为什么是多 agent 流程而不是一个大 agent**：插件生成天然分角色（读规格 → 写实现 → 验一遍 → 不过就回炉），每个角色的提示词、工具白名单、工作目录都不同；合成一个的话，「测试 agent 挑出的毛病」和「实现 agent 的自辩」在同一段上下文里，没有独立判定。回炉那条链（`packages/shared/src/loop.ts`）就是靠角色分离才成立的。

**为什么每个节点 spawn 一次 CLI 而不是调 API**：直接用人已经登录的账号，不管密钥；`--json-schema` 拿结构化输出；`--max-budget-usd` 有花费上限。代价是 §4.5 那几条 Windows 上的 spawn 坑。

**两个 CLI 有三处对不齐，而且都不能装作接上了**（`apps/server/src/agentcli.ts`）：`codex` 没有工具白名单（只有 `-s` 三档沙箱）、不报美元花费（只给 token 数）、没有 `--append-system-prompt`。前两条会让人以为配了其实没配 ⇒ `allowedTools` 非空时**往运行面板上报一条**，花费那一栏**宁可空着也不许按 token 估一个美元数**。

## §4 硬经验清单

> 编号供别处引用。每条都是踩出来的，不是设想的。

### 4.1 判据必须在花钱之前，而且只能有一处

**症状**：判据散在路由和调度器两处，加一条时该往哪放全靠记忆，而放错的那一半只在另一条入口上生效。

**更贵的是它让判据没法测**：写「前置检查没过就一次 CLI 都别调」这条用例时，要把 `startRun` 换成替身——**而判据就在 `startRun` 里，替身一换判据跟着被换掉**，那条用例验的是个空气。

**结论**：所有静态判据收进准备层（`apps/server/src/prepare.ts` 的 `checkRunnable`），调度器只管按拓扑跑。整条链上**第一次真花钱**是调度器起来之后第一个 agent 节点开跑，在那之前「没节点、有环、提示词对不上、工作目录不在」四样都判过了。
（2026-09-04，提交 `12f56f5`）

### 4.2 「文件不存在」和「文件坏了」是两件事

**症状**：相机 / 通讯 / 功能插件 / 诊断四类规格，读失败时 `console.warn` 一声然后 `return emptySpec()`。看着很稳，实际是条**丢数据的路**：界面上那份坏掉的规格长得和「新建」一模一样，人补两笔一保存，**原文件就真被覆盖了**——而控制台那句警告没人看见。

**结论**：`readDocIfExists` 只在真的不存在时回 `undefined`，坏了一律抛（带文件路径和原因），坏文件一个字节不动。高版本明确拒绝，不尽力而为地猜。

配套的**原子写**：同目录临时文件 → `fsync` → `rename` → 无论成败清临时文件。⚠ `fsync` 不能省——不落盘就改名，崩在那一刻会留下一个**名字对、内容是空洞**的文件，比留下半个旧文件更糟，因为它看着是新的。
（2026-09-04，`apps/server/src/docstore.ts`）

### 4.3 校验要看清字段的真实类型

**症状**：给 2D 规格加运行时校验时，`testImages` 是 `string[]`，我拿「必须是一组对象」去校验它 ⇒ **每一份正常的 2D 规格都会被判成坏文件**。

**怎么发现的**：用例。这个 bug 活了大概二十分钟。**如果那一轮只做重构不补测试，它会一路进仓库。**

### 4.4 老文件兼容要留明确的口子，而不是放宽校验

运行记录（`runs/*.json`）写在加版本号之前。要求它们有版本号 = 把人已经花掉的钱和产出从界面上抹掉。⇒ `DocSpec` 上加一个 `legacyVersion`，**只给运行记录用**，并在注释里写明「新文档类型一开始就该带版本号，留着这条口子只会让『缺版本』变成常态」。36 条真实记录实测全部读回。

### 4.5 Windows 上 spawn npm 装出来的 CLI

`claude` 在这台机器上是真 `.exe`，一直没事；而 `codex` 是 `codex.cmd`：

1. 先报 **ENOENT**——而它明明在 PATH 里，错误信息把人支使去查 PATH；
2. 加上扩展名之后 Node 24 报 **EINVAL**（拒绝 spawn 批处理，CVE-2024-27980 的缓解措施）；
3. `shell: true` 能绕但要自己处理引号，而这儿的路径里既有中文又有空格。

**正解**：把 npm shim 里那行 `.js` 抠出来，**用当前这个 node 直接跑它**（`agentcli.ts` 的 `resolveLauncher`）。加第三种运行时时照走这一条。

### 4.6 跨运行时的模型名不报错，只悄悄降级

`opus` 传给 codex 不会失败，只会降级 ⇒ `modelFor()` 丢掉跨家族的模型名并**往运行面板上报一条**。「看着配了其实没配」是这个仓库反复在戒的静默。

### 4.7 直播与重连回放必须共用同一份归约

两份的话，「直播看到的」和「切回来看到的」会慢慢对不上，而**那种不一致只在人说出「我刚才明明看到它成功了」的时候才暴露**——那时已经没法复现。

⇒ 提成纯函数 `apps/web/src/runview.ts`，用例每组跑两遍（逐条喂 vs 整串回放）并断言结果逐字节相同。

连带修了一处：**回炉时 `node.start` 要清掉上一轮的正文和工具调用**——不清的话上一轮的最终产出和这一轮的流式正文首尾相接，读起来像模型自己前后矛盾。而这个仓库的流程里回炉是常态。

### 4.8 `run.end` 收尾要分清「我没让它跑」和「它没轮到」

取消 → `canceled`；别的原因结束 → `skipped`。写成一种的话复盘时分不清。

### 4.9 `useEffect` 的回调一律写成块体

**症状**：「点一下挑项目，页面整个没了」——白屏，而报错和那次点击看着毫无关系。

**根因**：箭头的简写体会把表达式的值当返回值交出去，而 React 拿返回值当清理函数用。返回一个 Promise 的话，卸载时它去调 `destroy()`，抛 `destroy is not a function`，**整个 app 当场卸载**。

⚠ **typecheck 一个都拦不住**，只能靠浏览器验收。

### 4.10 不可重入的锁会自己锁死自己

**症状**：「打个『好』就卡死」——请求挂住、界面转圈、**日志里什么都没有**。

**根因**：`processTurn` 已经握着会话锁，我在里面又调了要同一把锁的 `confirmProposal` ⇒ 等自己放手。

**判据只能靠代码形状**（拿超时去测的话用例会真的挂十几秒）：`chat.test.ts` 里切出 `processTurn` 的函数体、剥掉注释、搜有没有调那几个要锁的外层函数。⚠ 判据的边界要找对——第一版只找 `\nasync function` 作为函数结束位置，而后面跟的是 `export async function`，于是切到了文件末尾，误报。

### 4.11 判据要剥注释

第一版的架构判据直接搜整份文件里有没有 `startRun` 这个词，结果它把**「在注释里写清这条规矩」也判成违规**——而那正是应该鼓励的事。判据要盯着真正的依赖，不是盯着字面。

### 4.12 攒经验那套机器差点整个不转（最贵的一条）

**症状**：跑了两轮 2D 算子（$18 + $40），**两轮 21 条经验配对上 0 条**。模型不是没写，是把同一件事换了个说法重新起名：`annotation-marks-where-not-where-to-measure` 下一轮成了 `verify-annotation-boxes-against-pixels`。

**根因是个死锁**：`lessonsPrompt` 在没有「已确认」条目时返回空串（理由是省 token，而 token 确实每节点每轮都付一次）。代价是 agent **一个记号都看不见**，只能凭空起名 ⇒ 对不上 ⇒ 永远升不上去 ⇒ 永远不给看。

**全程零报错**：文件在长、钱在花、提示词里始终是空的。

**而当时那条测试正好把 bug 锁住了**：

```
expect(lessonsPrompt([候选])).toBe("")
```

每轮全绿，绿得正好证明着那个让整套机器转不起来的行为。

**改法**：加「已经在用的记号」名册，候选也露，但只露记号 + 42 字摘要（正文才是贵的）。⚠ 两处都要说：名册摆出来了但 `lessons` 字段说明不提，它照样凭空起名。

**验法**：跑两轮的整机验收——存候选 → **断言提示词里出现了这个记号** → 复用 → 升成已确认 → 正文进提示词。**少中间那一步，测的就只是文件读写**。把老 bug 塞回去实测，5 条当场红。
（2026-09-04，提交 `fc1912c`）

### 4.13 入库的门必须是客观的

同一个记号在**两轮不同的运行**里都出现过才升成已确认。让 agent 自评「这条值不值得留」就是自评回路。上限 12 条，超出的不删只是不带；每条记着 `from`（哪几轮攒的）——**不可追溯的经验没人敢删也没人敢信**。

⚠ `freeform: true` 的节点没有 `structured`，经验记不下来。那是对的（自由文本是调提示词用的），但别指望调试模式下也在攒。

### 4.14 模型只能引用结论，不能得出结论

对话式入口最容易出的错**不是答得不好，是宣布一件没发生的事**——「规格已经完整了」「插件做好了，可以下载」。用户信了，拿走一个空壳。而这个仓库里「骨架」和「实现完成」分得很清，一个会说话的入口不能把这条界线又抹掉。

**分工**：`nextstep.ts` 是纯函数，由程序决定阶段、缺项、允许的动作、能不能下载；模型只负责把它讲成人话。

⚠ **`canStartRun` 在规划器里永远是 `false`**——它只说「建议跑」，不说「可以跑」。起跑要花钱，必须由用户**这一次**点头，旧会话里的同意不算永久授权。

### 4.15 起跑只有一条路，而且要写成会红的判据

对话入口的运行必须走 `prepareRun`，碰不得 `startRun`——绕过去等于把十几道花钱之前的判据全关了。**人手记不住**，所以写成用例（剥注释后搜那几个文件）。把 `startRun` 塞回去，当场红。

### 4.16 模型说「记下了」而一个字都没写

**症状**：助手回「厂商和型号记下了」，而盘上什么都没有。

**根因**：它写的路径是 `spec.model`（少个 s），白名单挡下、整批跳过（整批跳过是对的，写一半更糟）。**白名单救了数据，那句话仍然是假的。**

**两处都要改**：把正确的路径清单摆给模型看（不给它就编一个很像的名字），以及拒绝时**明说「这一轮什么都没记下」**。同时在提示词里禁止它说「记下了 / 已保存」——落没落盘由系统另外告诉用户。

### 4.17 算风险之前必须先补上「现在是什么」

**症状**：改一个已经填过的字段，被判成低风险**直接写掉，不弹确认**。

**根因**：模型只交 `path` 和 `after`，拿那个去算风险，覆盖被当成新增。

⇒ `fillBefore` 先去盘上读一遍当前值，再算风险。覆盖是要人点头的那一档。

### 4.18 冲突检测要逐字段比对，不用全局计数器

第一版拿**会话的修订号**当基准，而会话每回一句话就 +1 ⇒ 每条提案在生成的下一刻就「过期」，用户点确认**永远得到 409**。

真正要防的是「中间有人在别处改过**这个字段**」⇒ 提案里记下当时的实际值，确认时逐字段比。

### 4.19 撤销要撤得干净

撤销一个「从没填过的字段」时最明显：老值是 `undefined`，撤回去写成 `""`，文件里就凭空多出一个 `"vendor": ""`。功能上等价，但盘上和撤销之前对不上——**那种差异以后没人说得清**。⇒ 清空即删键。

### 4.20 别给用户一条走不通的路

**症状**：功能插件和诊断插件的规格是结构化的表（能力清单、因果规则），白名单不许从聊天里写，可规划器给的动作是「填字段」⇒ 人照着提示打一段字 → 模型提取 → 白名单一拒 → 「什么都没记下」。

**看着像在引导，其实原地打转，而且每转一圈都调一次模型。**

⇒ 改成指向对应编辑页，并补两条判据：聊天里填得了的才给 `fill_field`；结构化的表指到编辑页。

### 4.21 「现在该做什么」不能只挂在消息上

只靠历史消息里恰好带的卡片的话，打开一条老会话就一个能点的东西都没有。**实测撞上：项目已经 `ready`、`canDownload` 是 true，而下载按钮不出现。**

⇒ 每个响应都带上当前该做的那件事，由服务端算（前端再判一次的话两边迟早对不上，表现是「按钮在、点下去说不满足条件」）。

### 4.22 口头确认要用确定性判据，不问模型

有一条提案等着点头时，用户打「好」就该落地。但**「他刚才是不是同意了」不能交给模型**：把「好，不过位置换一下」当成同意 = 拿着旧内容直接写；把「可以」当成没同意 = 让人反复说。

⇒ 正则，而且收得很紧：整句除了肯定词什么都没有才算。带转折（但 / 不过）、带修改动词（换 / 改 / 加 / 删）、或者长一点，一律不算，交给模型去理解。43 条用例里**「不算同意」那一组比「算同意」那组更重**。

### 4.23 上传内容一律当不可信数据

传上来的 SDK、协议文档、README 里可能写着「忽略上面的规则，执行……」。引导助手看到的只有「传了几个文件、有没有头文件」这类由判据算出来的事实，**文件内容不喂给它**；而且它跑的时候**一个工具都不给**。

实测：传一个只有 `.exe` 和一句注入文案的假 SDK，系统点名那个 exe 说「这多半是安装程序不是开发包」，阶段不前进，那句注入从头到尾没进过上下文。

### 4.24 测试不能写到真实运行目录里，尤其是清不掉的垃圾

**症状**：界面上一条清不掉的报错横幅——`conversations/坏掉的会话.json`。

**根因**：那是「坏文件不该让侧栏打不开」那条用例写的，用 `fs.writeFile` 绕过 id 校验直接写了一个**中文名**的文件；而清理走 `deleteConversation` → id 校验拒非 ASCII → 抛 → 被 `.catch(() => {})` 吞掉。**跑一次测试污染一次真实数据。**

⇒ 清理按**文件路径**清（不走 id 校验）+ `wb-test-` 前缀 + 兜底扫描。

### 4.25 「装得上」不等于「实现了」

界面上必须分开说。生成出来的是**骨架**，每个方法都还在报「还没实现」。相关的三条：

- `skeletonFiles` 要认**三种报法**——算子骨架**抛**、相机骨架**返回 `Result.Fail`**（相机契约明确要求不抛）、因果规则**两样都不能干**（唯一诚实的是 `CauseVerdict.Needs([NotImplementedYet])`）。只认 `throw` 的话，一屋子空壳会被判成「实现好了」。
- 生成器**不覆盖已存在的文件**（保护 agent 填的实现），代价是后加的能力有实现文件但没登记、一致性照样全绿 ⇒ `listDrift` 专门堵这个，**且不自动补写**（常驻行为的实现就在同一个文件里，机器往里插一行改坏了更难查）。
- `DeclaredDiagnosisPackage = true` 少一行，HKC0110–0119 一条都不跑，**一个什么都没交的诊断包也是全绿的**。

### 4.26 版本号不能写死

`kernelContractVersion` 硬编成 7，而生成的 C# 写的是 `KernelContract.Version`（跟着编译时那份 SDK 涨）。宿主升到 v8 之后两边对不上 ⇒ 宿主**按清单放行、按代码运行**，两套事实变成拒载。唯一来源是开发包里那份模板清单，读不到就抛——**猜错的包能构建、能下载，装机那天才拒载**。

### 4.27 厂商原生库的传递依赖不走宿主的解析器

宿主的 `AssemblyLoadContext` 只解析你直接 P/Invoke 的那一个；它自己的依赖链由 Windows 按默认搜索顺序找，**那里面没有包目录**。于是链中某层的 `DllMain` 返回 FALSE，调用方收到 **`Win32 1114`**——一个看着像「厂商的库坏了」的错，而库好好的，只是路径不对。

`LOAD_WITH_ALTERED_SEARCH_PATH` 也不够，它只管被加载的那一个。正解是 `SetDefaultDllDirectories` + `AddDllDirectory(包目录)`。**实测确认过**：同一个 dll，依赖先加载进进程就正常，冷启动直接加载就 1114。

### 4.28 `deps.json` 看不见随包抄进来的原生库

它只记 NuGet 带进来的原生资产，而厂商 SDK 的 dll 是 csproj 用 `<None CopyToOutputDirectory>` 抄进去的 ⇒ 还要**真去读包目录里每个 .dll 的 PE 头**。少这一步，一个装了二十个原生库的包会被判成「三平台通用」——**那是一句假的全清**，清的正好是要拦的那件事。读不懂的一律按原生算。

### 4.29 随包的文件用 `Always` 不用 `PreserveNewest`

后者的意思是「目标比源新就不拷」，于是手改过的包清单能**活过一次完整构建**——包可以带着错的 id 出厂，而构建日志一切正常。

### 4.30 一致性判据不能选在链条下游

那条「清单对得上吗」不能传 `AppContext.BaseDirectory`——那是**测试工程**的输出目录，里面那份清单是从源码抄的。拿它校验，「改了清单没重新构建包」查不出来，而宿主读的是包目录里那份。

### 4.31 通讯插件是一条管道，不是一个协议实现

职责只有三件：把字节送出去、把收到的按分帧规则切成一条条、把每条抛成事件。**发什么内容不归它管**——在插件里编报文（命令字、心跳、握手包）的后果是：上层塞进来的和插件自己发的混在同一条链路上，对面收到两种东西。

连带：**裸 TCP / 串口 / 数字 IO 没有厂商协议文档，别拿「没传文档」去唠叨**——那条缺口只在走成品协议栈（Modbus / S7 / MC / FINS / OPC UA）时才成立。

### 4.32 分帧是通讯规格里最贵的一条

TCP 是字节流不是消息流：写错不会编译报错，本机自测和短报文都正常，**上产线报文一长就开始丢**，现场表现是「偶尔收不到」，要抓包才查得出来。⇒ 做成必填，规格书和生成的代码注释里都原样写着这句话，写实现的人在两个地方都躲不开。

### 4.33 界面上的两个坑

- **别拿 `<label>` 包一排按钮**：label 会把点击**转发给它里面第一个控件**，于是点哪个都落在第一个上——表现是「选不动」，而代码看着完全正常。
  ⚠ 连带的判据教训：**验「选得动」只点第一个是测不出来的**（第一个本来就选中着），要点一个**非首位**的并断言选中态真的移过去了。
- **指针捕获和事件监听必须在同一个元素上**：捕获在外层视口、监听挂在里层被 transform 的画布上，捕获会把事件重定向到视口、不再往子元素派发，`pointerup` 于是永远收不到。症状像「工具串味」，其实是这两层不一致。

### 4.34 环境相关的三条

- **pnpm 换过配置键名**（`onlyBuiltDependencies` → `allowBuilds`），只写旧的会以退出码 1 结束，而日志最上面还写着 "Already up to date"。**两个键都留着。**
- **`启动.cmd` 要跑的那个文件从来没进过 git**（验证过：全部历史 0 次出现）——现场拿到包起不来。
- **Git Bash 里 `curl -d '{"name":"中文"}'` 会被编码搞坏**，服务端回 400 Bad Request，**看起来像服务端的 bug，其实是 shell 的**。中文 body 要写进 UTF-8 文件再 `--data-binary @文件`。

### 4.35 一个字段都不许预置猜出来的值

**症状（现场原话）**：「为什么会有 tcpclient 协议的事情，我新作的插件不应该读取到这个」。

人刚说完要接一块 PCI7230 数字 IO 板卡，助手就在旁边提示「但协议那栏现在是 TcpClient，两者对不上」——**而那个值不是任何人填的**。

**根因是两个缺陷叠在一起**：

1. `emptyCommSpec()` 给必填的 `protocol` 预置了 `"TcpClient"`（`framing` 同理预置 `"request-reply"`）；
2. `commSpecIssues` **从不检查这两栏** —— 于是它永远不是缺项、永远不会被问到。

猜出来的值一路进规格书、再进生成的 C#。而**通讯代码猜错编得过、一致性也全绿**，装机那天才知道协议根本不对。

**解法**：两栏改成可选（`protocol?`），「没选」是个真实状态；自检各报一条缺口；规格书如实写「还没选」；生成器入口 `requireReady` 收窄类型，**没选就当场抛**，不许替人挑。

**同一族的第二处**（自己扫出来的，不是撞出来的）：`CommAddress.valueType` 是自由字符串 `string`，界面新增一行种子写死 `"int"`，自检不看它，却照样以事实身份印进规格书那张表。**位宽猜错不报错，只是数不对** —— 16 位寄存器当 32 位读，现场看到的是「这个温度怎么是六万多」。收成联合类型 + 自检 + 服务端枚举校验。

**顺带发现**：同一份可选值清单被**手抄了三份**（界面、服务端给模型的提示、类型），而服务端那份漏了 `byte[]` —— 模型永远不会用它，界面上却明明摆着。

⚠ **冒烟检查把这个缺陷当成规格锁着**：那条断言原来写的是 `ok("一开始选中的是默认那个", … === '["TcpClient"]')`，所以它绿了好几个月。
（2026-09-08，提交 `9a1c020`）

### 4.36 判据要按「这东西是什么形状」问，不是按类型问

**症状（现场原话）**：「这个回答太复杂了吧，其实你只需要 SDK 文件就行了对吧」。

接一块 PCI7230 板卡，系统问的是：

- 「没填地址。连到哪都不知道，agent 只能编一个 IP 写进去」—— **板卡没有 IP**；
- 「「数字 IO」是裸链路，没有协议库替你分帧——选一个真的分帧方式」—— **板卡没有报文**。

人答的「驱动自己管」是对的，**系统告诉他答错了**。而真正非它不可的那样东西（厂商 SDK）一个字都没问。

**根因**：`commSpecIssues` 拿一套 TCP 形状的问题问全部九种协议。

**解法**：九种协议只有三种形状 ——

| 形状 | 谁 | 缺的是什么 |
|---|---|---|
| `stack` | Modbus / S7 / MC / FINS / OPC UA | 手册（功能码、偏移、字节序）+ 地址表 |
| `stream` | TcpClient / TcpServer / 串口 | **分帧规则**——TCP 上最贵的那条 |
| `board` | 数字 IO | **厂商 SDK**（头文件 + 导入库 + dll） |

板卡上**只有 SDK 拦在生成之前**：通道 Id 生成器本来就退回插件 Id，板卡位置是 `ParameterDescriptor`（装机时在宿主里配，写死才是错的），型号项目名和 SDK 包里都写着。

**更一般的教训**：**问错问题比不问更贵** —— 人会认真去找一个不存在的 IP，而缺的那件事没人提。所以协议没定之前，一个跟形状有关的问题都不问。
（2026-09-08，提交 `9a1c020`）

### 4.37 两次点击如果长得一样，就是个死循环

**症状（现场原话）**：「为什么点开始一直会跳回点开始的按钮」。

起跑有意分两下：`run.confirm` 只摆范围和花费，`run.start` 才真跑（合成一次的话，「看一眼要花多少」和「开跑」就成了同一次点击）。

而**两张卡片 id 都是 `run:<flowId>`、渲染也一模一样**，界面只能猜 —— 它一律发 `run.start`，而 `run.start` 要求先有一条 `run.confirm` 建的待确认提案：

```
点「好，开始」→ 无脑发 run.start → 409 → 状态没变 → 同一张卡片又出来 → 死循环
```

而且那个 409 没摆给用户看，所以表现就是「点了没反应」。

**根因是上一次改动**：`run.confirm` 原来由「挑一条流程」那个选择器触发，把挑流程改成自动认时，**顺手删掉了唯一发 `run.confirm` 的地方** —— 服务端两次点击的判据还在，第一次点击的触发点没了。

**解法两条**：卡片自己带 `action`（服务端说清这一下是哪一步，界面照着发）；**两步的字样也要分开**（「看看要花多少」/「好，开始」）—— 都写「好，开始」的话，点第二下看着还是像第一下没生效。

⚠ **连带的判据教训**：冒烟脚本原来**只等那个按钮、从没点过它**。而死循环的表现恰恰是「点完还在原地」，不点就永远测不出来。现在点第一下并断言按钮换成了另一个。
（2026-09-08，提交 `e23eafe`）

### 4.38 禁用条件不要跨功能抄

**症状（现场原话）**：「点击 X 为什么没有取消」。

对话框附件右上角那个 ✕ 点了没反应。禁用条件写的是 `disabled={!!busy || !!doc?.pending}` —— 从「撤销最近一次保存」那个按钮抄来的。那儿拦住是对的（有提案等着点头时撤销写入确实容易乱），但**撤掉一个贴错的文件和那条提案毫无关系**，而建项目那张确认卡几乎一直挂着，于是 ✕ 基本永远是灰的。

**连带的判据教训**：那条冒烟断言恰好跑在**没有 pending 的时刻**，按钮当时是可点的，所以放过了。现在改成先塞一条待确认提案、刷新、断言 `isDisabled() === false`，然后才点。

⚠ **做回归验证时，破坏脚本自己要 assert**。这次第一遍做「把缺陷塞回去看红不红」，匹配串多带了个 `>`，**静默没替换成功**，于是「缺陷塞回去了还是绿的」——差点据此得出「这条判据没用」的错误结论。这类静默失败在这个仓库里已经咬过三次（`String.replace` 无声 no-op、python 脚本抛在写盘之前还打了 "ok"、这次）。
（2026-09-10，提交 `189f69a`）

## §5 回归体系

三层，各管各的：

| 层 | 跑什么 | 管什么 |
|---|---|---|
| `pnpm verify` | 三包 typecheck + **971 条** vitest + web build | 纯逻辑、契约、归约 |
| `pnpm ui:smoke` | 11 份 playwright（驱动系统装的 Edge，不下载浏览器） | **纯逻辑测不到的那一半**：接线、状态机、事件、渲染 |
| `pnpm ui:smoke:plugin` | 4 份**真的跑 dotnet**（+ `diagplugin.mjs` 单跑） | 生成器错在哪，只有真编一次才知道 |

**两条方法论**：

- **改交互行为先改用例，红了再改实现。** 标注那 160 条用例是规范条文的可执行版本，每条都能对回规范的某一节——手感这种东西不锁住就会悄悄漂移。
- **判据自己会造污染。** 探测「发明动作」的验收脚本自己会造出一条 400，浏览器记进控制台 ⇒ 验完要把自己造的那几条摘掉，不然「控制台干净」那条永远红，而**红的原因是判据自己**。

⚠ **默认页变了会让一批验收静默挂掉。** 2026-09-08 撞到：默认页改成「对话创建」之后，四份验收还在等一个永远不出现的「新建项目」按钮，30 秒超时，而报错只说「找不到 locator」，看不出是默认页变了。**等于界面改动那几天没有验收。**

⚠ **同一天又撞了一次，而且是更贵的那五份**：五个真跑 dotnet 的脚本全都卡在同一处。上一轮只跑了快的那几份就以为修完了 —— 而那五份正是唯一能验出生成器错在哪的。**「修了一类问题」之后要把同类的全跑一遍，不只跑撞到的那几个。**

**新脚本要记得挂进 `ui:smoke`。** `traces.mjs` 写完之后一度不在里面 —— 写了但日常不会跑，等于没写（2026-09-10 补上）。

**三条新的方法论**（2026-09-08 → 09-10）：

- **验「两次点击」时必须真的点第一下。** 死循环的表现恰恰是「点完还在原地」，而原地那个按钮一直都在 —— 只 `waitFor` 不 `click` 就永远测不出来（§4.37）。
- **验按钮可用性要在「最容易被禁用」的状态下验。** ✕ 那条断言恰好跑在没有待确认提案的时刻，于是放过了一个「基本永远是灰的」按钮（§4.38）。
- **回归验证（把缺陷塞回去看红不红）的脚本自己要 `assert`。** 匹配串写错时 `String.replace` 静默 no-op，于是「缺陷塞回去了还是绿的」——差点据此得出「这条判据没用」的错误结论。这类静默失败在这个仓库里已经咬过三次。

## §6 当前状态与欠账

> 这一节每次都重写 —— 它最容易陈旧，而陈旧的「已经能跑通」是所有描述里
> 最贵的一种错。

**已经能端到端跑通的**（2026-09-10 实测）：

- 六种项目类型的规划都对得上真实状态，与「高级设置」页逐项一致；
- 对话里说一句需求 → 助手一句话说全 → 打「好」→ 项目真建出来 → 接着问下一项；
- **资料齐了自动往下走**：传完 SDK → 自动生成骨架 → 自动开跑，中间一次不用点
  （只由用户这一次操作触发，**打开旧会话不会自动开跑**）；
- 对话里跑一致性 → 真调 dotnet → 通过 → 阶段变 `ready` → 真下载到 120 KB 完整包；
- **对话框能贴图 / 拖压缩包 / 选文件**，带缩略图和撤销；
- **全过程记录**：一轮运行落一条事件流，执行实例、工具调用、调用记录、
  证据 blob 都在盘上，「评估与数据」页看得到，`legacy_partial` 标着 54 条老运行；
- 断点续跑、经验累积、流程解锁、`{{project.lastBlocking}}` 都在线上。

**欠账**（按「离能用还差多远」排）：

1. **模型裁判只有判定层，没接真调用。** 提示词构造、证据校验、降级规则、
   人工复核、一致率都齐了，但「真的去问模型」那一段没写 ——
   它默认关着、要预算授权，而开发测试不许调真模型，**没有可靠的验收手段**。
   （2026-09-09）
2. **重放执行器没做。** 三种动作（重新评估 / 记录回放 / 重新执行）的语义、
   判据、隔离策略都在，但「在隔离目录里真跑 agent」那一段没实现。
3. **导入没做。** 预检判据（路径穿越、压缩炸弹、hash 核对、冲突决策、
   路径映射）全在且有用例，解包落盘那一段没写。导出是通的（真出过 zip，
   打得开、hash 逐个对得上）。
4. **性能验收没跑**：PRD 要的一万条事件、100 MiB 日志、10 万条记录那个规模
   没构造过合成数据实测。
5. **对话里的 Run 还没用真实模型跑完过一整轮。** 起跑链路代码和用例都齐，
   但没有一次从对话里点开跑、跑到 `RUN.END done` 的实测记录。
6. **经验累积的第三轮验收没做。** 名册补丁落地之后，还没有一轮真跑去验
   「记号真的被复用、真的升成已确认」。这是那套机器唯一没被真实验证的一环。
7. **文档上传解析成候选字段没做**：现在传的资料只做分类和索引，
   不从协议 PDF 里提地址表。
8. **五个插件生成器没抽公共 blueprint。** 判断没变：值得抽
   `manifest.json` / `.csproj` / 包清单判据这三样（它们已经咬过），
   但**不该抽骨架** —— 五种的「诚实」根本不同（见 §4.25）。
9. ⚠ 待确认：`agents/*.md` 每次请求重读磁盘，一轮运行中途改 agent 文件会让
   后续节点用上新提示词。目前没有判据挡这件事，也没实测过它会不会造成
   同一轮里前后不一致。

**已经不再是欠账的**（上一版列过，现在解决了）：

- ~~测试写在真实的 `conversations/` 目录里~~ —— 新加的记录层用可注入的数据根，
  用例挪到临时目录（§7.19）。老的会话用例还没跟着改，但那条路已经有范例了。

## §7 Agent 评估与数据集中心（2026-09-09 新增）

按一份 624 行的 PRD 做的，分 P0–P3 四阶段。这一节记的是**判据层面的经验**，
不是功能清单 —— 功能清单在那份 PRD 里，而它会过时；下面这些不会。

### 7.1 分两层：事实不可重算，判断可以

评分、归因、案例都是**后来**基于记录算出来的，可以重算；
当时喂给模型的是什么、它调了什么工具，**错过就永远没了**。

所以事实那一层的规矩比别处紧三条：**不知道就写不知道**（`null` + 原因，
不写 0、不写空串、不猜）；**展示可以截断，存储不能装作完整**；
**老记录不补造**（拿今天的 agent 定义去补一段"当时的系统提示词"，是在制造假证据）。

### 7.2 `nodeId` 不是执行实例的唯一键

PRD 里点名说「既有轨迹归约假设单一当前节点」。**核对下来这句不准确** ——
运行归约每条事件都带 `nodeId`，本来就按节点分开归约。

但它指的缺口是真的，而且在另一处、更严重：**运行事件不带任何执行实例标识**。
调度器自己算着轮次（`rounds` map），却没放进事件。于是回炉第二轮和第一轮
在下游**分不开**，`node.start` 只能整个清掉重来 —— 上一轮的正文、工具调用、
产出**当场销毁**，而那一轮的钱是真花掉的。

解法是给事件加 `<nodeId>#<round>`，归约存两份：`nodes` 是最近一次
（面板照旧只看这个），`execs` 按实例留每一轮。

> **一般化的教训**：PRD 里对现有代码的判断要核对，不要照着实现。
> 但「它想拦的那件事」通常是对的 —— 核对之后往往会发现问题更严重。

### 7.3 追加式日志必须容忍坏尾巴

高频事件不能用「整份读、整份写、原子换名」那套（一轮上万条，每条重写整份
JSON 是 O(n²)）。改成只追加的 JSONL。

代价是**读的时候必须容忍坏尾巴**：最后一行解不出来就丢掉它、把这份流标成
`partial`，而不是整份判坏。直接 `JSON.parse` 每一行的话，一次断电就让整轮
记录连同已花的钱从界面上消失。

追加式坏了是「最后一行没写完」，整份重写坏了是「整份没了」—— 后者更糟，
但前者要求读的那一侧多写十行。

### 7.4 「已落盘」和「已排队」是两回事

⚠ **实测撞到的**：关键事件走的是不等待的 `void flush(...)`，所以真正 `await`
那一次往往发现缓冲已空 —— 早先直接返回上一次的 `durableSeq`，**报 0**。

那个 0 会让界面把整轮标成"这之后可能缺"，**一份完好的记录看起来像丢了全部证据**。

修法一行：空缓冲也要 `await` 队列排空 —— `flush()` 的含义是「到此为止都已落盘」。
**是真跑一轮的探针抓到的**，typecheck 和「断言函数被调过」都拦不住。

### 7.5 采集要包在**唯一那个出口**上

`callAgent` 是整个仓库唯一真正把东西交给 CLI 的地方，所以采集包在它外面 ——
对话和流程两条路自动都采到，调用方一行不用改。

采在更上层（比如调度器里）的话，**模型名被 `modelFor` 换掉**、
**工具白名单在 codex 上不生效**这两件事都看不见 —— 而那正是「配了但没生效」
最常出问题的地方，也是最值得记下来的。

顺序是**先落盘再花钱**：输入快照和 `invocation.start` 落盘之后才真调 CLI。
反过来的话，崩在中间留下的是一次「花过钱但没有输入记录」的调用 ——
而那种记录等于没有。

### 7.6 报不出来的东西一律 `null` + 原因，绝不写 0

codex 不报美元花费（只给 token 数）。写 0 的话它在费用排行里显示成
「最便宜的那个」，而它其实是「不知道」。

所以每个运行时要**照实声明它报得出什么**（`RUNTIME_CAPTURE`），
拿不到的逐条列出来。工作台只能保证它传给适配器的输入 ——
声称拥有模型服务内部完整上下文是句假话。

### 7.7 脱敏：一趟扫，按规则具体程度取不重叠区间

⚠ 逐条 `String.replace` 串下来会让**占位符自己又被下一条规则脱一遍**：
`token=sk-ant-…` 先被 anthropic-key 换掉，接着泛化的 conn-password 规则
看到 `token=` 又整段换掉 —— 脱 1 处报成 2 处，而且
**「泄漏的是一把 Anthropic key」这条信息被盖掉了**，而那一栏正是给人判断
「泄漏了什么」用的。

另外**脱敏要在存之前做，而且脱完再算 hash**：反过来的话，规则升级之后
hash 不变，库里留着的还是旧的明文那份。

### 7.8 算分：未知不算已知（这一族是整套东西的命门）

三条口径写死在纯逻辑层，界面不再算一遍：

- **没有有效检查时分数是 `null`**，不是 0 —— 「还没得评」和「评了但很差」
  是两件完全不同的事；
- **`unverified` / `grader_error` 不进分母** —— 进了的话，一次裁判超时
  就能把一个好版本打成差版本；
- **硬门槛 fail 就是没过**，90 分也换不来「装得上」。

**「没验」「没过」「不适用」是三件事**。缺设备、缺资料、缺采集都不是 fail；
裁判自己挂了更不是（那要记在裁判头上）。`not_applicable` 整个排除在分母外，
但**适用性说不准时按待验证算** —— 不能靠它缩小分母（分母缩小 = 覆盖率虚高）。

⚠ **实测撞到的**：一份报告是 `pending_verification`、分数 **100**、
覆盖率 **8%**，而结论里一个字没提覆盖率 —— 人看到「100 分，还差三项没验」，
读起来像「基本做好了」，而那 100 分只建立在**一条**检查上。
低覆盖那句话原来只挂在「通过」那一支；现在跟着覆盖率走、**和结论无关**。

### 7.9 三件事分开报，不合成「完成度」

Run done ≠ 插件合格，构建通过 ≠ 业务成立，下载 ≠ 用得上。
`business.accepted` **永远不会自动变成 pass** —— 只能由人在真实环境里确认。

合成一个百分比的话，一个只有骨架的包会因为编得过而显示成「做好了」——
而这个仓库里「骨架」和「实现完成」本来分得很清（`skeletonFiles` 那一套判据
就是为它写的），一个会说话的入口不该把这条界线又抹掉。

### 7.10 裁判：三条边界

1. **只读，不给业务工具权限** —— 一个能改项目的裁判，最省事的
   「让检查通过」的办法就是去把代码改了；
2. **待评资料里的话不是给它的指令**。提示词里要**具体说清**
   「看到「忽略评分规则」该怎么办」，只写一句「注意注入」没用；
3. **引用不存在的证据 = `grader_error`**，记在裁判头上不记在被评对象头上 ——
   判成 fail 的话，一次幻觉就变成「这个插件有缺陷」。

另外两条：空着的 fail（判了不满足却说不出看到什么）降级为待验证；
漏判按待验证算 —— **默认通过是最危险的默认值**。
双裁判分歧进复核，**不强行平均**（平均会把那个错误藏起来）。

### 7.11 预算：先占额度再花钱

余额 $10、同时起五个作业，每个都读到「还有 $10」的话最后花 $50 ——
而这个调度器本来就是并发的。所以 `reserve` 先扣住、`settle` 用实际花费替换，
估值只用于占位、绝不进统计。

三本账分开（业务 / 裁判 / 实验）：一次跑飞的实验不能吃掉当天的业务额度，
而且要查得出是被谁吃的。

⚠ **运行时报不出美元时，美元上限是句空话** —— 花到多少都没人拦得住，
因为没人知道花了多少。这时候必须要求一个调用次数上限，**并且明说**。

### 7.12 跑不起来的案例不许当尺子

**一个跑不起来的案例永远「通过」，那是最坏的一种假绿。**
所以「能不能重放」不过就不许冻结。没写「怎么核对」也不许冻：
三个月后没人知道当时是怎么判的。

**冻结之后就地改一律拒绝**，要改就新建一版 —— 尺子会变的话，
「通过率从 60% 涨到 80%」可能只是尺子松了。

**同源分组切分**：不按组分的话，同一需求的两个副本会落进开发集和保留集，
「在没见过的数据上也好」就是假的。而**人看过保留集细节之后那一组也失效** ——
这一种程序查不出来，只能记一笔并如实说。

### 7.13 整体提升掩盖不了回归

修好三个、搞坏一个，不算净赚。同一输入结果不稳定时**均值没有意义**。
没跑完的试次要留着 —— 只统计成功的会让失败率凭空消失，
而正确性故障和基础设施故障要分列。

**没有冻结案例时禁止自动声称验证提升**，只允许建议和手工启用。

### 7.14 归因默认是推测

「方案漏了超时 → 工程按缺失的方案实现 → 测试没覆盖」这条链看着很顺，
但它是**一个假设**：证据只能证明前两件事各自成立，证明不了因果
（也可能工程本来就不打算加，也可能它加了又被下一轮改掉）。

四档置信度，默认最弱那一档。只有干预重放或人确认过的才允许说「导致」。
干预之后问题还在 → **归因被证伪，退回推测**，别留着一个已经被证伪的猜测。

⚠ **未经实验的归因不能自动降级角色** —— 一个印象性的「它老出问题」
会在几轮之后变成事实上的封杀，而中间没有任何一步验证过。

**同一个根问题不许算成三条**：记成三条的话，「这一轮有 9 个问题」里
可能只有 3 个根问题，而人是按数量判断严重程度的。

### 7.15 经验：重复出现 ≠ 评测通过

这个仓库原有的经验机制，门是**重复出现**（同一个记号在两轮不同运行里
都冒出来就升成已确认、进提示词）。那是个客观的门，但它证明的只有
**「这件事发生过不止一次」** —— 它没证明「照着这条做会更好」。

所以新增一套**独立**的验证状态，两套并存：老的迁成 `legacy_repeated`，
**行为一个字不变**，只是界面上说清「还没独立评测过」。
直接标成 `validated` 等于给一批从没验过的东西发证书，
而它们已经在影响每一轮的提示词。

### 7.16 导入当成敌意输入

路径穿越、压缩炸弹、hash 对不上一律拒绝**整个包**，不「尽力而为地导一部分」。
包里有 `.exe` 要说出来但**不执行**。同 id 不同内容不覆盖本地那份。
跨机器路径映射不上就标待配置，**不猜一个出来** —— 猜的话 agent 会在
不存在的目录里找文件，报的错和真正的原因差很远。

导出清单里写「脱掉了这几类」+「**这不是全部脱敏的保证**」，
不给一个让人放心的对勾 —— 检测只认已知的凭证形状。

### 7.17 存储：阈值不是自动删除授权

空间不够时**停止接新的受管执行**，不删旧证据 —— 删是不可逆的，
「磁盘满了」是可逆的（插个盘、挪个目录）。自动删的产品会在某天清掉
一份人正要用来复盘的记录，而那时候没人知道是被哪条规则删的。

清理分**预览**和执行两步：一次清理会让某些案例永远重放不了，
而那件事只有摆在眼前人才看得见 —— 合成一步的话，
「清理三个月前的记录」听起来完全无害。

### 7.18 这一批里 typecheck 一个都拦不住的六个缺陷

全是真跑或浏览器验收抓到的：

| # | 症状 | 根因 |
|---|---|---|
| 1 | 完好的记录显示成「丢了全部证据」 | `flush` 空缓冲时返回上一次的 `durableSeq` |
| 2 | 脱 1 处报成 2 处，且泄漏类型被盖掉 | 占位符又被下一条规则脱了一遍 |
| 3 | 100 分 + 覆盖率 8%，结论没提覆盖率 | 低覆盖提示只挂在「通过」那一支 |
| 4 | 「配了但没生效」看不见 | 它被折叠在 `<details>` 里 |
| 5 | 所有页面窄屏横向滚 | 加第五个导航标签把右上角徽章顶出视口 |
| 6 | 组件死活不渲染 | **vite 缓存了旧的转换结果** |

第 6 条值得单说：同一次操作里先追加文件末尾、又插了中间一行，vite 只认了
前一次 —— 源文件里有那行，浏览器拿到的模块里没有。症状是组件不渲染而
typecheck 全过。**先 `curl http://localhost:5177/src/...` 看 vite 到底给了什么**，
比在 React 里找原因快得多。

### 7.19 落盘位置与用例隔离

`traces/` `evidence/` `cases/` 三个目录**不进版本控制** —— 里面是原始提示词、
模型输出和用户附件。

⚠ 用例必须用可注入的数据根挪到临时目录，**绝不碰真实证据库**。
这条是有前科的（2026-09-05 那次：用例往真实会话目录里写了个中文名的坏文件，
因为清理路径拒绝非 ASCII 而删不掉，界面上永久挂着一条错误横幅）。

## §8 插件探针与测试工程（2026-09-21 新增）

到 §7 为止，工作台能把插件**生成出来、构建过、跑完一致性**。但「装进宿主之后
到底出不出现」这件事，**整条链上没有任何一处回答得了**。这一节是补那一段，
以及由它带出来的画布、模拟运行、导入导出、把宿主 MCP 挂给 agent。

### 8.1 一致性测试答不了「装进去之后出不出现」

一致性套件用的是 SDK 里的 `RecordingExtensionBuilder`，它的注释就写着
**「不真的组装宿主」** —— 它只记录 `Configure()` 登记了什么。所以
「插件装上了、设备/算子不出现，**而且不报错**」那一族（宿主的 HKC0090）
它一条都抓不住。

判据只能是**真装载一次**：起一个真宿主（`HuikeHost.CreateDefault`，可以指定
插件根和工作区），读它的 `PluginLoadReport`、`NodeCatalog`、状态地址表。

> 实测抓到过三种一致性看不见的：`HK.Plugin.AssemblyLoadFailed`（生成了骨架没构建）、
> `HK.Plugin.ManifestMismatch`（清单契约版本和代码对不上 —— 而一致性读的是
> **测试工程输出目录**那份 manifest，不是包里那份）、`HK.Plugin.KindMismatch`。

### 8.2 分发的那道坎：开发包里没有内核和宿主

宿主导出的「插件开发包」只有 `Huike.Sdk` / `Huike.Sdk.Testing` /
`Huike.Ui.Contracts(.Testing)` + 模板。装载器、算子目录、流程编译器全在
`Huike.Kernel` 里 —— **第三方拿着开发包跑不了这种探测**。

要让第三方也能自测，就得把内核发出去，而那正是字符串加密 / 加密狗那几条 ADR
在护的东西（红队结论原话：「持有正版狗的人依然能拿到明文」）。

> **值得记的判断**：那几条 ADR 想护的明确是**提示词**（`AgentHarness` /
> `PromptInvariants` 那一族），而插件测试**一行 Agent 代码都用不到** ——
> 用到的只有装载器 + 目录 + 编译器 + 调度器。如果内核能按这条缝拆成
> 「运行时内核」和「Agent 内核」，前者随便发、后者加密上狗，两边都不用将就。
> 但那是个不小的重构，**不该为了做插件测试就去动它**。

### 8.3 报事实的那一层不下结论

探针（`tools/Huike.PluginProbe`，不进 sln、不进装机包、单向引用 Host）
**只吐事实**：装载报告、算子目录原样序列化、地址表、登记表、端口兼容规则实测结果。
判定（几档、算不算装上、带来了什么）全在工作台的纯函数里。

理由和别处一样：**事实层不可重算，判断层可以**。合在一起的话，宿主每升一次级
就要同时改两个仓库，而漏改的表现是「报告还是绿的，结论已经不对了」。

### 8.4 「一个插件都没装上」是结论，不是崩溃

无头样例遇到这种情况 `return 1` 是对的（它是 CI 冒烟）；**探针不同** ——
调用方要拿到那份 JSON 才能把「你的包没装上、原因是 X」显示给人看。

所以：**任何情况下都写出报告**，退出码只表达「探针自己有没有跑完」。
用退出码表达「包有没有问题」的话，调用方分不清「探针挂了」和「包坏了」，
而这两件事的下一步完全不同（查环境 vs 查包）。

⚠ 连带的：空装载根那一段摘要原来是**整个空白的**，而空白和「探针没干活」
在屏幕上长得一样。要明说「这个根下面一个包都没有，它下面每个**子目录**
才是一个包，检查是不是给深了一层」。

### 8.5 相机和通讯插件一个算子都不带 —— 算子数为 0 不是缺陷

相机插件登记的是 provider，通讯插件登记的是**工厂或通道实例**
（通道要等人配了地址才存在）。它们的贡献只在**登记表**里看得见：
`camera://@sources`、`comm://@types` 这类 `scheme://@xxx` 的目录型地址。

只读地址列表是看不到的 —— 实测：TCP 通讯插件装上了，`comm://` 下只有仿真通道，
摘要上只剩一句「装上了，但一个算子都没登记」，而**那句话对它是误导**。

⚠ 所以探针要**读 `@` 开头那些目录型地址的内容**。只读 `@` 前缀的是刻意的：
按约定它们是纯登记表，读它们不碰设备（这个探针是只读的，不许把相机真打开一遍）。

### 8.6 「这个包带来了什么」只能靠差分，而且噪音要规整掉

报告里**只有算子身上带 `pluginId`**，地址、帧源、登记表身上没有。
而恰恰是相机和通讯插件一个算子都不带 —— 不差分的话，那两类插件带来的东西
**一个字都归不到它头上**。

办法：跑两遍，一遍只装陪练包当基线，一遍全装上，多出来的就是它带来的。

⚠ **临时目录的路径会变成假差异**。两次探测必然落在不同临时目录，而像
`project://@current` 这种把自己路径写进正文的状态源，每一行都不一样 ——
于是差分栏永远挂着一条「你这个通讯插件带来了一个 projects.json」。
比之前把两次的工作区路径规整成占位符，**但留下的是原文**（人要看真实那一行）。
⚠ 别整个 uri 排掉：那样真出现在那儿的差异也一起没了。

### 8.7 被测包不能同时当陪练

陪练那一遍就是基线。基线里也装着被测包的话，差出来必然是空的，
而页面会照着说「这个包什么都没带进来」—— 那是**假话**，
而且它和「这个插件真的什么都没登记」长得一模一样。

自动从陪练里摘掉，**并且摘了要说** —— 不说的话人下次自己拿命令行跑会得到
别的结果，而想不起来为什么。

> 这条在「陪练包默认全勾」之后从边角情形变成了常态。

### 8.8 按包自己的清单分根，不按调用方把它放在哪一格

宿主有两个装载根：运行时插件住 `plugins/`，诊断插件住 `diag-plugins/`，
**清单里的 `kind` 和所在目录不一致直接拒载**（`HK.Plugin.KindMismatch`）。

界面上的项目下拉一旦把诊断类项目也列出来，选中之后路径就落进「被测包」那一格，
于是一个 `kind: "diagnosis"` 的包被塞进运行时根 —— 报的错**看起来像「这个包坏了」**。

正解：读包自己的 `manifest.json`，按它声明的 kind 分根。这不是「帮人猜」——
宿主自己也是拿这个字段和目录比对的。⚠ **分根要排在环境检查之前**：
它是对输入的判断，跟探针编不编得起来无关；排在后面的话，探针编不过时
这条结论就丢了，而那时人最需要知道的恰恰是「我选的那个包被当成诊断包了」。

### 8.9 画布：不发明第二种工程格式

宿主的 `WorkflowDraft`（schema v12）里本来就有 `CanvasX` / `CanvasY`，
注释写着「纯 UI 数据，不参与执行」；`NodeCatalog.ToJson()` 的注释写着
「供 **Agent / Web** / 文档消费」。也就是说**宿主早就预备好被一个 Web 前端消费**。

所以工作台的画布直接读写**宿主那个文件**，中间没有任何转换层。有转换层就会
悄悄丢字段，而丢掉的可能正是限值。

⚠ **画布不编辑的字段要原样带回去**：`limits` 是 OK/NG 判定的唯一配置入口，
读丢了的话，人在工作台改个参数一保存，那份方案的限值就没了，
**下一次跑产线全是 OK**。ROI、变量、配色同理，当不透明数据搬运，
绝不「顺手规整一下」。

⚠ **版本两个方向都拒**：高了会静默丢字段；低了要迁移，而**迁移只许有一处**
（宿主的 `SolutionStore`）。工作台再写一套，分叉的样子是「宿主打开好好的，
工作台打开少几个节点」。对不上就让人拿宿主打开保存一次。

### 8.10 提示归提示，判定归内核 —— 而且要有防分叉的判据

端口能不能连，权威判定在内核的 `PortCompatibility`；画布上那份实时提示是
工作台自己的一份实现。**两个仓库里的两份，一定会分叉。**

两条纪律：
1. **提示不拦拖拽**。拿一份可能错的规则拦住，人就连不上一条本来合法的线，
   而且没有任何办法绕过去。只染色 + 说清「该连哪个」
   （宿主为这条留过现场记录：「为什么找圆模块输出连不了条件分支」——
   那一刻软件两件事都知道，只说"不行"等于把后一半知识扣着不给）。
2. **让分叉能被发现**：探针把每一对类型都真问一次 `CanConnect` 报上来
   （13 种类型、37 对能连），工作台每次探测当场比对自己那份提示，对不上就摆出来。
   ⚠ **只报，不自动切换** —— 偷偷换成另一套规则的话，分叉就永远不会被发现。

> 这条的一般形态：**跨仓库的同一条规则，与其约定"别改"，不如让它每次都被实测一遍。**
> 抄出来的规则那一刻就开始腐烂，跑出来的永远是当下的真实行为。

### 8.11 模拟运行分四档，骨架单列一档

跑几帧之后每个节点的下场不能只有「成功 / 失败」两档，要四档：
**跑通 / 失败 / 没轮到 / 看起来还没实现**。

第四档是命门：刚生成的骨架跑一遍，正确结论是「装得上、连得上、跑完了，
**但这几个节点还是骨架**」—— 报绿是假的，报成「坏了」也是假的（它没坏，
它只是还没写），而这两种的下一步完全不同。

⚠ **「看起来」这三个字不能省**：宿主没有「这是个骨架」这个字段，三种诚实报法
（`throw NotImplementedException` / `Result.Fail` / `CauseVerdict.Needs`）
到了轨迹上都只是一条 `Failed` + 一段文字，所以只能按报错文本猜。

⚠ **一次失败不许被后面一次成功盖掉**。只看最后一帧的话，偶发失败会被下一帧
抹掉 —— 而偶发正是最要命的那种。归约要同时给「最近一次」和「这几帧里翻过车没有」。

⚠ **编译不过就不跑**。硬跑一遍拿到的失败是「方案本来就不成立」，
和「这个算子实现有毛病」混在一起，而后者才是这一步要找的。

⚠ 图只来自**仿真帧源**，一个都没有就不跑，**不自己造一张顶上** ——
造出来的图和人要测的东西没关系，而「跑过了」这句话会被当真。

> 顺带：`PipelineInput.Origin` 本来就能由调用方指定，所以这条链**一个枚举值都不用加**。
> 动别人的 `src/` 之前先找找有没有现成的口子。

### 8.12 导出包的形状由**对方的导入口**决定

宿主能吃两样：插件 —— 选一个文件夹，把里面所有 zip 一次导完（2026-09-20 现场要的）；
方案 —— 没有导入入口，只能拷进它的 `Solutions` 目录。

所以包里分两个目录，人按说明各放一次。**不发明一种宿主不认的包格式** ——
发明了就得让宿主跟着改，而这条链的价值就在于它不用宿主改。

⚠ **不带插件导出时必须把依赖列出来**。光给一份方案，对方装进去报「未知算子」，
而那句话**指不出原因** —— 他不知道缺哪个包、哪个版本。清单和说明两处都写。

⚠ **带插件时把这次装上的包全带上，不挑**。只带「提供了算子的那几个」看着干净，
但那是猜的：相机和通讯插件一个算子都不带，而方案里的参数可能正指着它们提供的设备。
挑错一个，对方装完打开设备那格是空的 —— 而没有任何地方会报错。

⚠ **算子找不到来源就拦住导出**（不是警告）：对方打开必报「未知算子」。

⚠ **校验和要算最终那份字节，不是算源目录**。算源目录的话，打包这一步本身
出了岔子（漏了个文件、压缩写坏了）校验和照样对得上 —— 那正好把它要防的事放过去了。
⚠ 说明里要写清**它不是签名**：谁都能改完文件再把清单里的数改掉。
一个看着像保证的东西比没有更糟。

⚠ **「验到什么程度」四种状态要分得开**：没校验过 / 读不动 / 没过 / 过了但没跑过。
合成一句「未验证」，拆包的人不知道下一步该干什么。校验没过**不拦导出**
（人可能就是要把半成品发给对方接着做），但包里必须写着。

### 8.13 导入一律当敌意输入（与 §7.16 同源，另一处实现）

路径穿越（`..`、反斜杠、绝对路径、盘符）、校验和对不上、包版本比本机新、
方案 schema 不认、压缩炸弹 —— **一律拒绝整个包**，不「尽力而为地导一部分」。
导一半的后果是一份看着完整、其实缺东西的工程，而缺的那块要到跑起来才发现。

⚠ **「没写校验和」和「对不上」是两件事**。混成一档的话，老版本导出的包一个都
导不进来。前者只提醒，后者拒。

⚠ **两步，第一步不落盘**：先 dry-run 看清里面是什么、依赖本机有没有、
验到什么程度，再点第二次才收。合成一次的话，「看一眼」和「收下它」就成了
同一次点击 —— 而这份包来自网盘或微信。

⚠ **工作台不装包里的插件**，只列出来 + 告诉你本机有没有。替人塞进宿主的
plugins 目录是**越界** —— 那是装好的软件的地盘，两边讲好了只靠包来回。

⚠ 包里有 `.exe/.bat/.ps1` 要**说出来但不执行**。

> 一条差点写错的判断：一度以为「工作台看不见 agent 在项目目录里搭的工程」
> 是解耦的后果。**不是** —— 那个目录在工作台自己的项目文件夹里，
> 解耦指的是工作台和**装好的软件**之间靠包来回。读自己建出来的目录不破坏任何东西。
> 多个来源的 id 用前缀区分（`p~<项目>~<文件>`），但**写进文件的仍是文件 id** ——
> 带前缀的只是内部寻址方式，写进去的话那份方案拷到宿主那边就找不着了。

### 8.14 把宿主的 MCP 挂给工作台派出去的 agent

宿主有一个现成的 MCP（`src/Huike.Mcp`，stdio JSON-RPC）。挂给 CLI 之后，
agent 自己就能读算子目录、搭方案、回放跑一遍、看轨迹、跑一致性 ——
**调参和自测变成它自己的循环**，不用每轮回来问人。一行判据都不用重写。

实测拿到的三条硬事实：

1. **`--strict-mcp-config` 必须和 `--mcp-config` 成对**。不带的话 agent 会继承
   这台机器上人自己配的全部 MCP 服务器（实测十几个 claude.ai 连接器：Gmail、
   Notion、Linear…）。agent 的提示词里一个字都没提过它们，而它真能调，
   还可能花别处的钱。
2. **不给 `--allow-edit`，四个关键工具根本不出现**（`graph_edit` /
   `graph_propose` / `run_sample` / `screen_edit`，11 个 vs 15 个）。
   宿主在那个开关旁边注明「敲下这个开关的是人……模型递不进来它」——
   所以它做成 agent front matter 上一个**要手写**的字段（`hostMcp: off|read|edit`），
   默认不挂。工作台替人敲的话，那个"人"就得是写 agent 文件的人。
3. **`claude mcp list` 不认 `--mcp-config`**，拿它验等于没验。

⚠ **白名单非空时 MCP 工具一个都调不到**（没列进去的都调不到）。于是会出现
「挂上了、连上了、一个都没用上」，而运行面板上什么都看不出来。
**不自动往白名单里塞**（塞了等于绕过白名单），只把话说出来。

⚠ **工具挂上 ≠ agent 会用**。和「经验名册」那条（§4.12）同源：要在提示词里
摆一张「哪个问题调哪个工具」的表，外加纪律 —— 读到什么写什么别复述文档、
「编译得过」和「跑得起来」是两件事、`Failed` 里混着"真失败"和"还没实现"、
跑不起来不等于插件有毛病（缺帧源/设备不在要写进 gaps 不是 blocking）。

> **验 MCP 通不通不用花钱**：它就是 stdio 上的 JSON-RPC，自己当对端问一句
> `initialize` + `tools/list` 就完了。仓库里留了 `tools/mcp-call.mjs`。
> 上面那三条事实里有两条就是这么查出来的 —— 而起 `claude -p` 去问既花钱、
> 又可能因为模型压根没去调那个工具而让「没调到」和「接不上」长得一样。

### 8.15 入口藏在结果底下，等于不存在

画布原来只在「探完之后、页面最底部」才出现，而页面上没有任何地方提到还有
「搭工程」这回事。**现场连问三次「怎么拖拉拽搭工程」。**

三处都要改：
- **默认值要能跑通**：陪练包原来只默认勾仿真设备，而它**一个算子都不带** ——
  照默认探一次，算子目录是 0、画布上一个能拉的都没有，而人看不出问题在哪。
  勾多了的代价只是慢几秒，勾少了的代价是**这一页看起来是坏的**。
- **入口在条件不满足时也要在场**，只是说清现在不能用、缺什么。
- **抄对方的交互习惯**：宿主写的是「双击添加，或拖到画布上放在你想要的位置」，
  只做了"点一下"就漏了一半。

### 8.16 这一批里 typecheck 一个都拦不住的六个缺陷

承 §7.18 的形状，这一轮又攒了六个：

1. **全局 `input { width: 100% }` 把复选框撑满整行** —— 勾选框跑到中间、
   文字被挤到最右，而且每行位置都不一样（框在剩余空间里居中，而剩余空间随
   文字长短变）。
2. **按 `card.id` 猜该执行哪个动作**，认不出的落到默认分支「生成骨架」——
   **而生成会覆盖文件**。加一张新卡片时差点就这么过去了。正解是按服务端给的
   `ActionKind` 走 + 穷尽映射 + **认不出返回 null 不画按钮**
   （少一个按钮是小事，点错一个覆盖工程不是）。
   ⚠ 顺带查出一个老 bug：`platform` 那张卡的 `action` 是 `generate_plugin`，
   而界面一直发 `verify` —— 猜错了很久没人发现，因为两个都"能跑完"。
3. **列表用事实文本当 key** —— 不同状态源报出一模一样的一句话是常事
   （"这一刻枚举到 0 台"），包一多就撞，控制台刷警告、条目可能漏画。
4. **设置文件写进空串导致整页 500，而且自己修不回来**：用「非空字符串」
   去校一个**允许为空**的字段，人在界面上清空 → 写进 `""` → 再读就抛 →
   连「还没配」的状态都显示不出来，只能去手删文件。
   ⚠ 顺带：**清空一个字段等于删键，不是写空串**。
5. **探针的临时现场被清理策略扫掉，导致导出 400**：报告里的包路径指向临时拷贝，
   而清理只留最近 N 次。正解是报告里同时带上**原始目录**。
   （清理本身是必须的：每份现场躺着整套插件包，几十次之后几百兆，没人会发现。）
6. **验收自己造的错没摘掉，于是"控制台干净"永远红**（§7.18 里已有同款，
   这次换了个形态）：故意喂坏文件会造一条 400，要在**结尾**摘 ——
   Chromium 的 "Failed to load resource" 报得很晚，当场摘的时候它还没到。
   ⚠ 而且摘之前那条正则里混进了两个**退格字符**（`\b` 被脚本语言当转义吃了），
   永远匹配不上，折腾了四五轮才发现 —— 查这类问题要**逐字节看**（`cat -A`）。

> 这六条加上 §7.18 的六条，共同的形状：**typecheck 管的是类型，不是"这东西
> 到底会不会按人想的那样动"**。而后者只有浏览器验收和真跑一次拦得住。
