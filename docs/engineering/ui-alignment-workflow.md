## §1 一轮循环的形状

十七轮下来是固定的四拍，**每一拍的产物都留在仓库里**，所以隔一周回来不用重新解释上下文：

```
人给一个"不对"的信号          AI 回去读一手材料           改                收尾
─────────────────────       ─────────────────       ────────        ──────────────────
一句话（"和旧项目不一样"）   把旧项目那个文件读完      写代码           判据跑绿 + 存一帧截图
一张截图（并排）             按 300dpi 渲开量像素                      文档追加一节：
三条口头指出                 翻 SOP 手册第 N 页                          ✅ 落了地的
一份旧源码路径               读参照软件的配置 json                       ⚠ 这一轮的教训
                                                                        还欠 / 卡在哪
```

四个真实例子（出处均在 `冲压通用软件` 仓库）：

| 轮 | 人给的输入 | AI 做的 | 收尾 |
|---|---|---|---|
| `progress.md` §6.2 | 一句话："和旧项目功能不一样"，没有细节 | 把旧项目 `Solution/RunUserContrlGrid.cs` **3529 行读完**，列出六行差异对照表 | 判据 507 全绿 ＋ 另存一张截图 ＋ 三条"还欠" |
| §6.3 | SOP p3 那张整屏截图，和我们这屏**并排** | 分三块产出：操作逻辑 / 版式（每个数写明量到的依据）/ 照抄的细节表 | 诚实写下"还剩的可见差异" |
| §6.4 | 一句质问："为什么界面还是这样" | 自查根因：**从来没跑过一帧**，"那个按钮之前只会改一行字" | 新增真起线的 `InspectionRunner`；单列"这一轮抓到的两个真 bug" |
| §6.5 | 三条口头指出 | 逐条改 | **判据里加反证**（"三项下拉、七项面板"），防这条哪天退化成"全都一样" |

到第十三轮，"人说功能不一样"这种模糊输入已经被固化成标准程序：
**逐行读旧源码的方法名，做成 ✅/❌ 对照表**，✅ 标"早有"、❌ 标"这一轮补上"。

## §2 落地清单：换个项目照这个起步

1. **先取证，并给每个来源标可信度。** `ui-alignment.md` §0 就是一张取证表：
   SOP 手册（28 页 119 张真实界面截图）＝ ⭐ 一手最可信；参照软件落盘的配置 `json`、
   图标文件名、驱动 dll 清单 ＝ ⭐ 一手；**`BorderCollie.exe` / `Core.dll` 的字符串 ＝ ❌ 挖不出来**
   （Qt release，字符串在压缩资源里）。
   ⚠ 同时写下已知的取证风险：手册截图是 1.1.0 而安装包是 1.5.0，"个别细节以实物为准"；
   手册标题是某个具体项目的 SOP，**不是通用手册**。
   PDF 正文按页抽成纯文本另存一份（该项目是 `sop_grid.txt`），截图裁成 `docs/img/*.png`——
   这样每一轮 AI 引的是同一份东西。

2. **先对齐术语，再谈别的。** 三方术语表（参照 A / 参照 B / 内核 / **本项目采用** / 照谁），
   一行一个词。不做这张表，后面每一轮都在打"你说的方案是哪个方案"的嘴仗。

3. **写死一条仲裁规则，全文只写一次。**
   > 两边都有的照 BorderCollie，BorderCollie 没有的照 JET2DVis，实现手法参考 HuikeAgentNew。

   有了它，"这块该照谁"不用每轮重问一遍；违反它的时候也能一句话点出来（见 §3.5）。

4. **一份长驻的对齐清单当契约。** `docs/ui-alignment.md` 是这套方法的核心：
   - 前半（§1–§15）是**按界面分区的逐条依据**，每条标参照谁；
   - 后半（§16）是**按轮追加的落地对照**，每轮一个小节，标题写这轮做了什么；
   - 结尾一张**总欠账表**：欠什么 / 哪一节 / **卡在哪**。

   这个项目里**没有 CLAUDE.md**——这份文档就是提示词本身，每轮开工让 AI 先读它。

5. **要人拍板的用 ⚠ 标出来，不猜。** 拍板之后原地改成
   `### ✅ 已定（YYYY-MM-DD）：…`，并在 §15 汇总成"已确认的 N 项决定"表。
   该项目 5 条里最典型的一条：「数据源 vs 拍照次序」——两套软件是两个概念，
   定为**只做一个**，**位置照 A、语义取 B**，并把代价写下来（"A 那种用法没有了，用换型代替"）。

6. **每轮收尾必须留三样**：判据条数、一帧真渲染截图、以及这一轮的 ⚠ 教训和"还欠"。

## §3 硬经验清单

编号是给引用用的。每条都真的发生过。

### 3.1 AI 做界面反复犯的六类错

| # | 类型 | 长什么样 |
|---|---|---|
| **3.1.1** | **粒度做错（把两级压成一级）** | 旧项目的尺寸表格是两级（选算子 ＋ 选测量类型，18 种），做成了一级。**为什么不行不是洁癖**：一键批量设置没法用了（它是对"同一种量的所有序号"一起设），而且列号不再是序号——现场说"第 7 根针超了"对不上屏上第 7 列 |
| **3.1.2** | **摆了但没接线** | 按钮"之前只会改一行字"；`ToolAddRequested` 这个事件**没有任何人接**，"而按钮看起来完全正常：有图标、有名字、按得动、还有悬停提示"；某个 88 条判据全绿的页面**根本没接进界面**，主页那块是一段占位文字 |
| **3.1.3** | **判据绿了但屏幕不对** | 断的是 `ItemsSource` 里有几条 ⇒ 屏上少了三行照样绿；截图判据只断"截得出一帧、尺寸不是 0" ⇒ 屏上少两行照样绿 |
| **3.1.4** | **给错误做法配了一段漂亮论证** | 「表格跑过才有列」这条**还写了一大段理由，理由是错的**：现场顺序是先填上下限、再开机跑，二十七根针的公差照图纸录，不是跑出来的 |
| **3.1.5** | **权限/职责漏到错的屏上** | 「这个算子跑不跑」是编辑屏的事，摆到运行屏表头上＝把编辑权限漏进只读那一屏；补偿值按绝对行号判显隐 ⇒ 第二组往后照样露着，**权限等于没挂** |
| **3.1.6** | **同一件事在屏上两个入口** | 方案列只读 ＋ 表格顶上另摆一个算子下拉；折线单选圆点 ＋ 结果行点击定位。"两个入口迟早各说各的"。第十三轮的处理是：右键「批量设置」**不另开小窗**，只把人送到底下那条一键设置跟前 |

### 3.2 数是量出来的，不是挑出来的

原先那套配色（`#F5F6F8` 底、圆角 4）是**照感觉配的**。改成实测：
**把参照物截图按 300dpi 渲开，逐块取众数像素**，产出一张"量到 vs 原先"的十行对照表，
**量到的值写进代码常量后面的注释**。尺寸同理：字号对着截图的行高倒推、主菜单按钮 72×34 → 64×26。

量完才明白的两条：
- 结果绿点必须比大写 OK 那个绿**深**——点只有 10px，亮绿压白底上几乎看不见，"原先两处用的是同一支笔"；
- 选中行是**浅底黑字不是反白**——反白之后"一列里选中的那一行反而最难读，而人正盯着它"。

⚠ 松一档看着舒服是有代价的："图像区和尺寸表格各少一截——而那两块才是人一直在看的东西"。

### 3.3 判据钉的是关系，不是色值

`ShellChromeTests.cs:694-726` 断六条**关系**：结果绿点比运行绿深、数据格底和行底亮度差 > 6、
选中底色亮度 > 170 且与正文对比 > 120、控件边比分隔线深、窗口底不是纯白。
理由写在注释里：**色值随时能调，这几条一调就会悄悄回来。**
具体令牌用**对象身份**验（`Assert.Same(StampingTheme.XxxBrush, ctrl.Foreground)`），不比字符串。

### 3.4 配色换了四次，每次都在找"更硬的出处"

感觉配 → 截图量出来 → 内核亮色（"结构照参照物、色温照内核"）→ web 三版并排选的「冷灰工业」→
**最后落在 AntdUI**。定在 AntdUI 的理由是**出处硬**：旧项目有 25 个文件 `using AntdUI`，
完整源码就在仓库里，色值读自它的 `Style/Style.cs` 又和 Ant Design 上游 `seed.ts` 核过。
⚠ 中间"走过两版弯路，都是自己调色调出来的"：一版现场说"太冷"、一版"太暖"。

⚠ **手头的 `artifact-design` / `dataviz` 这类 skill 是给网页 artifact 用的，
对 Avalonia 桌面程序不适用**——别指望用它"美化"一个桌面程序。

### 3.5 照抄的四种姿势，以及两类事故

**姿势**：
- **有意不照抄的，理由写在代码里**（该项目三处：运行按钮写动作不写状态、配置区是盖一层不是另开窗口、总览三种布局外加 4×4 墙）；
- **可以拆开抄**：术语表里「拍照次序」直接标注"**位置照 A / 语义照 B**"；
- **照结构不照理由**：流程画布网格"照内核但不照抄理由"——内核格距是拖动吸附格，我们不给人拖节点，所以格距取"一行算子的行距"；
- **没出处的要声明**：「插件」那一页两个参照软件都没有，先写明"没有出处"，再单独论证为什么还要加。

**事故一：抄错了对象。** 表格组宽抄成了 B 的 10，而这几页说好以 A 为准（A 的 SOP 截图是 1~9 / 10~18 / 19~27）；
默认列数 10 → 27（A 那份 `tableHeader` 的长度）。改完正好三组填满表格区。
同类事故在第十轮被**提前拦住**：通讯配置差点按 B 的"多设备"模型做，先写一句"A 没有多设备，这几页以 A 为准"。

**事故二：抄了但语义不同——这类会造成安全事故。**

| 事故 | 后果 |
|---|---|
| 参照软件的 `check_flag` 是定长 128 数组、默认**全 false** | 照抄的话，**一份填好了上下限的新方案永远判不出 NG**：每一格公差都对、每一件都超，而屏上一片绿。少勾一个框和少填一个公差，屏上长得完全不一样，后果一样严重，而前者没有任何一处会提醒 |
| 一键设置的 `×` 档是 `x * (1 + val)`，**是比例不是倍数** | 当成倍数实现，填 `0.05` 把 ±0.05 的公差缩到二十分之一 ⇒ 下一班全线判 NG |
| 旧项目审计表有 15 列，含工号/部门/会签那五格 | 我们没有账号库也没有指纹会签。**"摆五个永远空的列，人会一直以为是'这几次没记上'"**——缺什么写成一句话摆在页底，比五个空列诚实 |
| 参照物列头是编号 | 它那几个算子的测量项是现场背下来的；**我们的算子来自插件目录，编号等于让人去猜"第 3 列是什么"**。折中：单值写名字+单位，出多个值的才写编号 |
| 旧项目只有管理员改得动上下限 | 放宽到工程师＋管理员。理由：按那个分法**门禁在现场会被绕过去**（大家共用管理员账号），"绕过去之后所有改动的留痕都记在同一个人名下——比放宽一级严重得多" |

⚠ **纯措辞也要回抄**：数据页按钮从「更新」改回「**查询**」、「从/到」改回「起始时间/终止时间」——
"同一台机器上两套软件并存过，措辞对不上时人会以为是两个功能"。

### 3.6 欠账表：区分"做不了"和"忘了"

三层欠账：每轮小节末尾的「还欠」＋ 分节专题表 ＋ 结尾那张**总表（欠什么 / 哪一节 / 卡在哪）**。
"卡在哪"必须写清是外部依赖还是纯界面活——"纯界面活，没有外部依赖" / "缺驱动那一侧" /
"缺账号库" / "没有历史库"。

- **做不了的单起一节**：第十五轮的标题就是「剩下那几条：**做不了，不是忘了**」，五条各写为什么。
  反复出现的判据是两句：**"编一个名字比留着更糟"**、**"猜一个数比说不出来更糟"**。
- **缺的功能在界面上摆着并说明缺什么**（琥珀色一条），**不留白、也不写"开发中"**。
- **唯一让欠账自动失效的办法：把它编码进判据。** 多语言那条豁免单
  `NotYetTranslated` 是**待办清单不是豁免清单**——每一条是屏上一处还在说中文的地方，
  清完一处删一行；**删空了这一条就变成一道真闸门**（现在确实是空数组，注释写明"留空是为了告诉下一个人别往里加"）。

⚠ **这张表自己也会烂。** 截至 2026-09-22，总表上有两条**已经在后面的轮次里做完了却还挂着**
（上下限落盘 → 第十四轮已做；列数跟着方案存 → 第十五轮已做），而且其中一条的描述还停留在
"一组 10 列"——那是第七轮就改掉的数。**手写的欠账表没有任何机制发现自己过期**，
只有 `NotYetTranslated` 那种编码进判据的不会。

### 3.7 别的项目也能直接用的几条

1. **"绿了"和"看着对"是两回事**：看截图时要拿参照物那张**并排比**，不是只确认"画出来了"。
   这条写在判据注释里，而人自己也违反过——"我把那块白当成'列少的正常结果'放过去了"。
2. **判据要断屏上那几个字，不断数据源里有几条。**
3. **每条新规矩配一条反证**，防它退化（"三项下拉、七项面板"；"中文屏上同一段扫描必须点出一大片"）。
4. **判据要跑现场那块屏的分辨率**：1440×900 和 1280×800 两档。"只按开发机那块大屏验是不够的"，现场工控机常见的是 1280。
5. **放不下不要拍阈值，要量**：先拍了个"小于 1360 就收起来"，1280 下照样切。改成把整排摆出来问一句"要多宽"，
   放不下再**按既定顺序**收（先收设备名，再收模具号，**型号永远留着**），收起来要在悬停里说得出为什么。
6. **两种"改不了"必须分成两句话**（没权限 / 现在不是改它的时候）——下一步完全不同。
   **改不动的时候就别给人操作**，别让他做完一整套才发现什么都没发生。**灰着就是个哑巴**：灰掉的按钮必须有悬停说明为什么。
7. **静默回退是最贵的 bug**——字体名没装静默退回雅黑、限值查不到就"总是合格"、缩放留 0。
   凡是"屏上看起来正常"的失败路径都要单独钉一条判据。
8. **先出静态稿定方向，但只用来定方向**：web 画布出三版 1440×900 静态稿（结构和跑着的那屏完全一样、只换视觉），
   并排比完再动生产代码。⚠ 值得的是"三版并排看一眼就定了，比'改代码→编译→跑判据→看截图'快一个数量级"；
   ⚠ 不值得的是**HTML/CSS 和 code-only Avalonia 之间只能搬 token，不能搬代码**。所以它不适合当日常。

## §4 界面怎么验（这套方法的地基）

没有这一层，上面那套"人指出、AI 改"的循环撑不过三轮——因为**人无法每轮把每一屏都看一遍**。

### 4.1 无头会话：`tests/Stamping.TestKit/HeadlessUi.cs`（79 行，注释比代码多）

- `HeadlessApp` **故意不用产品的 `App`**（产品的会起真实宿主、装插件、鉴权），但**主题走真实的 `StampingTheme.Apply`**；
- ⚠ **`UseHeadlessDrawing = false` 是有意的**：保留 Skia ＋ 真字体，才有真实布局和几何命中，
  `window.MouseDown(pt)` 才算得出"点在哪个控件上"。**关掉渲染时几何查询恒 false，只能退回断对象图**；
- 整个程序集共用一个会话，`Run(Action)` 把碰控件的操作 dispatch 到 UI 线程；
- `Mount.Root(page, w, h)` **把页面挂到真实 `Window` 上再 Show/Measure/Arrange**，返回的 `IDisposable` 强制关窗。
  三条踩坑写在类注释里：**不挂根 `Bounds` 恒 0（假绿）**、不关窗全套跑会以字体错误报红、`ScrollViewer` 内容要等模板应用才进逻辑树；
- ⚠ **Avalonia 对没显示过的子树不做模板实例化**：判据得先切过去、跑一次 `Dispatcher.RunJobs()` 再量。
  第一次撞上的表现是"控件明明 new 出来了，判据说找不到"；
- ⚠ xUnit 的 `[CollectionDefinition]` 按程序集认，**放不进 TestKit**，每个测试工程各留三行。
- **模拟真实输入而不是直接调 handler**：全仓 `MouseDown` 25 次、`MouseUp` 25、`MouseMove` 16、键盘 6。

### 4.2 找控件按名字，不按位置

**产品侧做成可测接缝**：`ParameterPanel.cs:211` 和 `DimensionTablePage.cs:950` 各有一个
`public T? Find<T>(string name)`，配套 **162 个** `public const string …Name` 常量。
**判据引的是常量，不是字符串字面量。** 按坐标找的只有一处，是刻意的输入模拟。

### 4.3 截图分两层

| 层 | 做什么 | 在哪 |
|---|---|---|
| **存盘给人看** | 每屏 `CaptureRenderedFrame()` → 存 `artifacts/shots/*.png`，**每轮先清空旧图**。只断"画得出来、尺寸非 0" | `StartupTests.cs:294-360` 等 7 处 |
| **逐像素扫** | `CaptureRenderedFrame()` → `GCHandle` 钉住托管数组 → `CopyPixels` → 扫一块区域逐像素比 BGR 阈值 | `ImageReadoutTests.cs:185-223` |

只断"截得出一帧"那层为什么还留着：**Avalonia 的 `Render` 抛异常时只把那块画空——不炸、不报错、不写日志。**

⚠ 逐像素那条的阈值**和配色令牌直接挂钩**：画布从 `#303030` 改到 `#262626` 时，旧阈值当场把整块画布数成读数。
注释里记着这件事，等于声明"配色一改这条判据就会红"。

⚠ **无头会话一整套判据共用一个鼠标**：上一条停在哪儿下一条就从哪儿接着算，量之前必须先把光标挪开。
（2026-09-21 真红过。）

### 4.4 扫描式判据：正面判法，而不是查词典

- `LanguageCoverageTests.cs`：遍历所有 `IsEffectivelyVisible` 的 `TextBlock`，
  用 `\p{IsCJKUnifiedIdeographs}` 正则判**还剩不剩汉字**。**这是正面判法**——比"检查词典有没有某个键"强，
  插值拼出来的句子也逃不掉。闸门覆盖主页所有布局 ＋ 编辑页 ＋ 每一块配置区 × 英/越两语。
  两张豁免单**语义严格分开**：`NotYetTranslated`（待办，现为空）和 `Quoted`（只放插件作者原话 / 内核判定原话）；
  **豁免按控件名前缀，不按文字**。提示里带的路径要先剔掉（那是数据性汉字）。
  ⚠ 两条反证：中文屏上这段扫描必须点出一大片（证明它不是空转）、切回中文要真变回中文
  （"只验切出去的话，一个把所有字换成英文常量的实现也能过"）。
  ⚠ 语言是**进程级全局**而判据并行跑：判据直接查词典、不切当前语言，切了的必须在 `finally` 里还原。
  "单跑绿、整套红，而红的位置和这一组毫无关系。"
- `ClippedTextTests.cs`：查**屏上有没有字被切掉**。这类毛病**判据全绿、截图也"差不多"**：
  84px 的框里塞七个字，屏上是「需要工程师或管理」——最后那个「员」没了，而那半句正是"该怎么办"。
  写这条判据自己踩的三个坑都记下来了：
  1. ⚠ **拿 `DesiredSize` 比是错的**——它是量完之后被约束夹过的值；要用 `FormattedText` 量**不受约束的自然宽度**；
  2. 只比宽度会漏一类：文字自己没被截，是被**祖先 `ClipToBounds`** 切的；
  3. 要用 `IsEffectivelyVisible` 而不是 `IsVisible`——藏起来那屏的控件还留着上次布局的尺寸。

  同文件还有一条：**非空白字量出 0 宽 ⇒ 这套字体画不出来**。它抓到全角空格 `U+3000` 在这套字体上是 0 宽，
  源码写「冲压通用软件　0.1.0　NexAI」屏上挤成一团，而断文本内容的判据一路全绿。
- `CatalogTermsTests.cs`：从**真实插件目录**把算子的悬停简介、参数显示名、分组名、枚举候选值全收进来，
  断中文词在英/越两本词典里都有。⚠ 内核对没声明显示名的枚举值直接拿 C# 成员名顶上，**所以中文界面也会冒英文**。

### 4.5 "摆了但没接线"那一类怎么钉

全仓最系统化的一类，注释里反复出现"只断对象图照样全绿"。四个样板：

1. **清空按钮通到上层**：订阅事件计数 → `RaiseEvent(Click)` → 断收到 1 次；
   **还额外断悬停提示里不许再出现"还没接上"**（它以前就是个装饰按钮）。
2. **点组标题真的能折起来再点能展开**：用真实 `Click` 而非直接改状态；断的是**身子 `IsVisible == false`**
   而不是被清空（清空会丢掉人正在打的字）。只断"折叠状态改了"的话，按钮被盖住 / 没接 Click 也是绿的。
3. **点按钮要带着身份跳出去**："断的是点下去发生了什么，不是按钮挂上了"——断回调收到的是那条泳道的 id，不只是切了页签。
4. **补偿值那一行在每一组都藏得住**：断第二组的那个框也藏住，失败消息直接写
   "第二组的补偿值还露着——权限只挡住了第一组"。

⚠ **同一帧上多问一次**：在 Snap 出来的那一帧上顺手断「方案列的数据源和实际渲出的文本逐项相等」。
单独一条判据问不出来——它是从干净窗口直接切过去的，而人真的那条路是"开机总览 → 切单相机"，
**容器 realize 的时机不一样**。

⚠ **判据里不许往真的插件目录落盘**：七个测试工程并行跑、同时提级同一个暂存目录，
把某个相机驱动削得只剩一个 dll，症状是**那台相机的驱动悄悄没了**。
