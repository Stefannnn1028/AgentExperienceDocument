# 图像标注交互规范

> 生成日期：**2026-08-26**（林工 / fuzhao.lin@nexai-tech.co）
> 来源：`HuikeAgent` 仓库 `CYImageProcessToolkit/DrawViewer/Draw.cs`（4960 行）及其
> `DrawViewerToolkits.cs`、`Define.cs`、`ShapeData.cs`。
> 用途：**把标注类型和交互手势固定下来，任何新项目、任何渲染库照这份实现，手感一致。**

这份文档和本库其他文档不一样：**它不是某个项目的交接，是一份跨项目的契约。**
`Draw.cs` 是目前唯一完整的实现，所以它是事实标准；这里做的是把"代码里长成这样"
提炼成"应该长成这样"，好让别的渲染库照着写。

## §1 标注类型总表

`ShapeType` 枚举共 13 个值，`None` 之外 12 种可画（`Define.cs:11-27`）。
掩膜（Mask）不在这个枚举里，在 GDI+ 那套子系统，单列在末行。

> **存储形式的有意偏差（2026-08-27 定）**：`Draw.cs` 把旋转矩形存成 9 个点，
> 参考实现改存 `(cx, cy, w, h, rad)`，9 个手柄由它推。理由见 §6.14 —— 结论是
> **9 个点作为派生手柄有用，作为存储是冗余的**。

| # | 类型 | 用途 | 存储点数 | 定形参数 |
|---|---|---|---|---|
| 1 | `Rectangle` 正矩形 | 轴对齐 ROI | 2（左上、右下） | — |
| 2 | `RotateRectangle` 旋转矩形 | 跟随工件姿态的 ROI、形状模板区 | 9（见 §3.2） | `Rad` `Width` `Height` `Center` |
| 3 | `Circle` 圆 | 圆形特征、圆孔 | 2（圆心、圆周点） | — |
| 4 | `Ellipse` 椭圆 | 斜视角下的圆 | 2 | `Ellipse` |
| 5 | `Polygon` 多边形 | 不规则 ROI | N（≥3） | `IsClose` `Rad`（可整体旋转） |
| 6 | `Line` 直线 | 边、基准线、测距 | 2 | `Rad` `Width`(长度) `Height`(判定带宽) `CapCount` `CapLength` |
| 7 | `Point` 点 | 基准原点、单点标记 | 1 | — |
| 8 | `String` 文字 | 图上批注 | 1（锚点） | `Font` `StringSize` |
| 9 | `Brush` 画笔笔迹 | 涂抹式分割标注 | N（轨迹采样点） | `BrushWidth`（图像像素） |
| 10 | `LineCaliper` 直线卡尺 | 沿直线的一排边缘检测窗 | 2 + 2 手柄 | `CaliperHeight` `CaliperWidth` `CapCount` `FlipOrientation` |
| 11 | `CircleCaliper` 圆卡尺 | 沿圆周的一圈检测窗 | 2 + 3 手柄 | 同上 + `Rad` |
| 12 | `ArcCaliper` 弧卡尺 | 沿一段圆弧的检测窗 | 2 + 3 手柄 | 同上 + `SweepRad` |
| 13 | `Mask` 掩膜 | 排除区 | N | GDI+ 子系统，`ContourDrawings/Operation/DrawMask.cs` |

**类型分组**（决定交互模板，见 §3）：

- **两点定形**：矩形、圆、椭圆、直线 —— 拖对角线/半径生成
- **九点旋转矩形**：单独一套，§3.2
- **N 点链**：多边形、画笔笔迹、掩膜
- **单点**：点、文字
- **卡尺族**：三种，共用"骨架 + 窗高 + 窗宽 + 窗数"的四参数模型

## §2 统一交互模型

### 2.1 状态机

`ShapeState`（`Define.cs:29-36`）五态：

```
        新建                完成一次绘制             点中已有图元
Drawing ────▶ Modify ◀──────────────────  Done ◀──┐
   │            │                          ▲       │
   │            └── 右键点在图元外 ─────────┘       │
   │                                              │
   └── Esc / 取消 ─────────────────────────────────┘

HighLight       悬停高亮，松开回 Done
KeepHighLight   钉住的高亮，点一下回 Done
```

**关键约定**：绘制完成后**不回 `Done`，直接进 `Modify`**（`Draw.cs:3361`）。
人画完一个框，十有八九马上要调；退回只读态会逼人再点一次。

### 2.2 命中优先级（所有类型统一）

`Modify` 态下按下鼠标，**从上往下逐条判，命中即停**：

1. **旋转手柄** —— 只有旋转矩形和多边形有
2. **顶点/控制点手柄** —— `SelectPoint()`，返回索引或 -1
3. **图元内部** —— 各类型自己的 `IsPointIn*()`，命中即"整体挪"
4. **边上**（仅多边形）—— `CheckPntInLines()`，命中则**在该处插入一个顶点**

顺序不能换。旋转手柄画在图元外面但离得近，放在顶点之后会被顶点抢走；
多边形的"边"判定放在"内部"之前，会让人想拖动图元时莫名其妙加出一个顶点。

### 2.3 屏幕空间常量（**必须除以缩放**）

| 常量 | 值 | 出处 |
|---|---|---|
| 手柄命中半径 | `5 / scale` 图像像素 | `Draw.cs:2241` |
| 旋转手柄伸出长度 | `25 / scale` 图像像素 | `Draw.cs:92` |
| 已完成图元线宽 | `2 / scale` | `Draw.cs:3741` |
| 绘制中线宽 | `1 / scale` | `Draw.cs:3742` |

这四个量都是**屏幕尺度**的：人的手指和眼睛不会因为图放大了就变精细。
写成固定图像像素的后果：放到 8 倍时手柄挤成一坨点不中，缩到 0.1 倍时手柄糊满整张图。

### 2.4 坐标规则

- **一切几何存图像原始像素**，不存屏幕坐标。图缩放、平移、换窗口宽度，屏幕坐标全错，
  而算子要的是原图坐标。
- 屏幕 → 图像的换算只在事件入口做一次（`GetPointInImage()`）。
- 角度统一用**弧度**存 `Rad`，`Angle`（度）只作展示。
  混用两种单位是这类代码最常见的错误源。

### 2.5 拖拽必须用"起始快照 + 总位移"

按下时记住**原始几何**和**落点**，每次移动从这两个量重算，
**不要**按上一帧的增量累加。多边形整体旋转就是这么做的（`Draw.cs:2340-2345`：
`m_PolygonRotateSnapshot` + `m_PolygonRotateDownRad` + `m_PolygonRotateBaseRad`）。

逐帧累加 + 每帧取整，拖一段之后能偏出好几个像素，而且**看不出来**——
标注偏三个像素，算子里就是三个像素的系统误差。

## §3 逐类型手柄与交互

### 3.1 两点定形（矩形、圆、椭圆、直线）

| 阶段 | 手势 |
|---|---|
| 画 | 按下 → 拖 → 松开。`Polygon` 只有两个点，第二个点跟着鼠标 |
| 选 | 点图元内部 |
| 挪 | 拖图元内部 |
| 改 | 拖两个控制点之一 |

- 矩形：`[0]` 左上、`[1]` 右下
- 圆：`[0]` 圆心、`[1]` 圆周上一点，半径 = 两点距离
- 直线：`[0]` `[1]` 两端点；`Height` 是判定带宽（默认 `20`，`Draw.cs:79`），
  不是可见线宽 —— 命中判定按这个带宽算，否则细线根本点不中

### 3.2 旋转矩形（九点模型）

**这是最值得照抄的一套。** `Polygon` 固定 9 个点：

```
        [0] 旋转手柄（自 [4] 沿 Rad 方向伸出 25/scale）
             ↑
   [1]──────[2]──────[3]          [1][3][5][7] = 四个角
    │                 │           [2][4][6][8] = 四条边的中点
   [8]     中心      [4]  →Rad    [4] = +Rad 方向的边中点
    │                 │           [8] = -Rad 方向的边中点
   [7]──────[6]──────[5]
```

- `Width` = 沿 `Rad` 方向的边距（`[4]`↔`[8]`）
- `Height` = 垂直方向的边距
- `Center` = `[1]` 与 `[5]` 的中点（一组对角）

**四种拖拽行为**（`Draw.cs:2659-2930`）：

| 拖什么 | 行为 | 不变量 |
|---|---|---|
| `[0]` 旋转手柄 | `Rad = atan2(mouse - Center)`，八点全部按 Center/W/H/Rad 重建 | **中心、宽、高不变** |
| `[1][3][5][7]` 角 | 该角跟随鼠标，**对角固定**，另两角由 `GetRectanglePoints(Rad, 拖动角, 对角)` 推出 | **角度不变** |
| `[2][4][6][8]` 边中点 | 把鼠标投影到"中心↔对边中点"这条线上（`GetPointInLine`） | **角度不变、另一维不变** |
| 内部 | 全部点平移 | 角度、宽、高全不变 |

角拖动只改两维、边拖动只改一维，这个区分是手感的关键。
把边中点做成"自由跟随鼠标"会让矩形在拖边时悄悄变斜。

**画的手势**（`Draw.cs:2249-2276` + `3342-3362`）：按下播下 9 个点、拖对角线、
松开时按 `[1]`/`[5]` 的对角**生成轴对齐矩形**（`Rad=0`），然后用旋转手柄转到位。
不是"三次点击定中心和方向"。

> ⚠ 待确认：`DrawOptByMouseLeftClick` 里还有一条"中心 → 边中点，两次点击"的旋转矩形
> 创建路径（`Draw.cs:3597-3620`）。按 WinForms 的 MouseDown→MouseUp→MouseClick 顺序，
> MouseDown 已经把 `Polygon` 填成 9 个点，那条路径的 `case 0/1/3` 都匹配不上，
> 应为死代码。清理前先确认没有别的入口在用。

### 3.3 多边形

| 手势 | 行为 |
|---|---|
| 画 | 逐点**单击**加顶点；双击或右键收尾 |
| 加顶点 | `Modify` 态下点在**边上**，就在那插一个（`Draw.cs:2352-2360`） |
| 删顶点 | **右键点顶点**，且删完仍 ≥3 点才删；只剩 3 点时退化为弹菜单（`Draw.cs:3646-3660`） |
| 挪顶点 | 拖顶点手柄 |
| 整体挪 | 拖内部 |
| 整体旋转 | 拖旋转手柄——位置在**包围盒中心沿 `Rad-π/2`** 偏移 `25/scale`（`Rad=0` 时竖直向上，`Draw.cs:1409-1430`） |

"少于 3 点不给删"必须在**删之前**判，并且给人一句话说明。静默拒绝会让人以为交互坏了。

### 3.4 点 / 文字

单点锚定，拖锚点即挪。文字额外有 `Font`、`StringSize`；
`StringSize` 决定命中矩形 —— 没有它，文字标注点不中。

### 3.5 画笔笔迹

| 阶段 | 手势 |
|---|---|
| 画 | 按下落第一个采样点，移动**连续采点**，松开成一条笔迹 |
| 完成后 | **自动保持画笔模式**，可以接着画下一条（`Draw.cs:3307-3320`） |
| 命中 | 点到轨迹任一段的距离 < `BrushWidth/2`（`IsPointInBrush`） |

涂抹类标注的特点是"一次画很多条"，画完退出工具模式会让人每条都要重选一次工具。

### 3.6 掩膜

GDI+ 子系统，接口是 `AddPoint` / `MovePoint` / `EndDraw` / `Modify`
（`ContourDrawings/Operation/DrawBase.cs`）。语义与多边形一致，
差别是它表示**排除区**，渲染上应与普通 ROI 明显区分（一般用斜纹或半透明覆盖）。

### 3.7 卡尺族（三种，四参数模型）

三种卡尺共用一套模型：**骨架 + 窗高 + 窗宽 + 窗数**。

| | 骨架 | 骨架点 | 附加参数 |
|---|---|---|---|
| `LineCaliper` | 一条线段 | `[0]` `[1]` 两端 | — |
| `CircleCaliper` | 整圆 | `[0]` 圆心、`[1]` 圆周点 | `Rad`（起始角） |
| `ArcCaliper` | 一段弧 | `[0]` 圆心、`[1]` 弧起点 | `Rad` + `SweepRad`（默认 `π/2`） |

四个参数：

| 参数 | 含义 | 默认 |
|---|---|---|
| `CaliperHeight` | 每个检测窗**沿骨架法向**的高度 | `20` |
| `CaliperWidth` | 每个检测窗**沿骨架切向**的宽度 | `10` |
| `CapCount` | 沿骨架均布多少个窗 | 直线 `4`，圆/弧 `8` |
| `FlipOrientation` | 窗朝骨架的哪一侧 | 由拖拽方向的**符号**自动决定 |

**手柄布局**（`Draw.cs:4703-4900`）：骨架点之后追加专用手柄，
第一个检测窗（`t0 = 0.5/CapCount` 处）上挂两个：

- **窗高手柄** —— 沿法向偏 `CaliperHeight/2`
- **窗宽手柄** —— 沿切向偏 `CaliperWidth/2`

拖窗高手柄时取**带符号的法向投影**：
`CaliperHeight = 2·max(1, |signed|)`，而 `FlipOrientation = signed < 0`
（`Draw.cs:2958-2971`）。一个手势同时定了大小和朝向，不用再给一个"翻转"按钮。

圆/弧卡尺的手柄索引：`[2]` 旋转（圆）/弧终点（弧）、`[3]` 窗高、`[4]` 窗宽。

## §4 画布导航

| 操作 | 行为 |
|---|---|
| 滚轮 | 缩放，**以光标为锚点** |
| 中键拖 | 平移，光标变 `SizeAll` |
| 缩放系数 | 每格 `×1.25` / `÷1.25` |
| 缩放范围 | `0.05` ~ `100` |

锚点缩放的算法（`Draw.cs:3734-3740`）：

```
u = (mx - posX) / oldScale        # 光标下的图像坐标
v = (my - posY) / oldScale
posX = mx - u * newScale          # 缩放后让同一个图像点仍在光标下
posY = my - v * newScale
```

以画布中心或左上角为锚点缩放，人放大到一半就会把目标弄丢，只能反复平移找回来。

**缩放后必须重算屏幕空间的派生量**：线宽、旋转手柄位置（`Draw.cs:3741-3746`）。
漏了这一步的症状是"缩放之后旋转手柄跑到框里面去了"。

## §5 换渲染库要提供什么

规范本身与渲染库无关。任何渲染库要落地它，只需提供这四件事：

1. **图元绘制**：折线、多边形、圆/椭圆、弧、线段、文字、圆点
2. **屏幕↔图像坐标变换**：缩放 + 平移，能取到当前 scale
3. **指针事件**：按下 / 移动 / 抬起，且**支持指针捕获**（见 §6.3）
4. **重绘触发**：一次交互一帧，别一个事件重绘一次

**命中判定不要依赖渲染库。** §2.2 的优先级和各类型的 `IsPointIn*` 全部用纯几何算，
放在独立模块里。理由是：几何是纯函数、好推理、好测；指针事件全是状态。
两边混在一起时，改一个拖拽 bug 会顺手把坐标算错。

**参考实现已经这么分了**（§8 有目录树）：纯逻辑八个模块 + 一个渲染组件 + 一个事件组件。
换渲染库时纯逻辑那八个**原样复用**，只重写渲染和事件绑定。
连"画"也做成了纯状态转移（起手 → 若干次更新 → 收尾），
好处是画一个框能脱离浏览器断言坐标 —— 绘制手势也进了单测。

选型上的取舍：

| | 命中判定 | 大图多图元 | 适用 |
|---|---|---|---|
| SVG（DOM） | 渲染库给（点到哪个元素就是哪个） | 上百个图元开始卡 | 图元少、要 CSS 悬停态 |
| Canvas 2D / Direct2D | **自己算** | 快得多 | 工业大图、图元多 |

用 SVG 时仍然建议**自己算命中**：一旦以后换 Canvas，交互逻辑不用重写。

## §6 硬经验清单

编号可被引用。

**6.1 手柄尺寸必须是屏幕尺度，除以 scale。**
写成固定图像像素，放大 8 倍时手柄挤成一坨点不中，缩小到 0.1 倍时手柄糊满整张图。
涉及四个量：命中半径、旋转手柄长度、两种线宽（§2.3）。

**6.2 缩放锚点必须是光标，不是画布中心。**
以中心为锚点，人放大到一半就把目标弄丢了，只能反复平移找回来。算法见 §4。

**6.3 拖拽必须用指针捕获（pointer capture），不要靠 mouseleave 复位。**
在 Chromium 上实测：拖到一半图元重绘，会收到一个 `relatedTarget` 为 `null` 的
**假 `mouseleave`**，把拖拽状态清掉。症状是"矩形偶尔能画出来、线段几乎画不出来"，
看着像这个工具坏了。同理，捕获期间原生 `dblclick` 收不到，双击要自己按时间间隔判。
（`个人工作台` 2026-08-26 踩到，Direct2D 那套因为是窗口级消息不受影响。）

**6.4 拖拽按"起始快照 + 总位移"算，不要逐帧累加。**
每帧取整一次，拖一段能偏出好几个像素，而且看不出来。标注偏三个像素，
算子里就是三个像素的系统误差。（§2.5）

**6.5 命中优先级不能换顺序。**
旋转手柄 → 顶点 → 图元内部 → 边（插点）。旋转手柄放顶点后面会被顶点抢；
"边"放"内部"前面，会让人想挪图元时莫名加出一个顶点。（§2.2）

**6.6 角拖两维、边拖一维，这个区分是旋转矩形手感的关键。**
把边中点做成自由跟随鼠标，矩形会在拖边时悄悄变斜。（§3.2）

**6.7 画完直接进 `Modify`，不要退回只读。**
人画完一个框十有八九马上要调，退回只读态是逼人再点一次。

**6.8 涂抹类工具画完要保持工具模式。**
画笔的使用特点是一次画很多条，每条都要重选工具是不可接受的。（§3.5）

**6.9 拒绝一个操作时必须说为什么。**
"少于 3 点不给删顶点"要在删之前判并给出提示。静默拒绝会让人以为交互坏了。

**6.10 卡尺的窗高手柄用带符号投影，一个手势同时定大小和朝向。**
`CaliperHeight = 2·max(1,|signed|)`，`FlipOrientation = signed < 0`。
省掉一个"翻转"按钮。（§3.7）

**6.11 直线的命中带宽和可见线宽是两回事。**
`Height` 默认 20 像素，是判定带；照可见线宽（1~2 px）判定的话，细线根本点不中。

**6.12 几何存图像原始像素，角度统一存弧度。**
屏幕坐标一缩放就全错。度/弧度混用是这类代码最常见的错误源。（§2.4）

**6.13 缩放之后要重算屏幕空间的派生量。**
线宽和旋转手柄位置都依赖 scale。漏了的症状是"缩放之后旋转手柄跑到框里面去了"。

以下 6.14–6.27 来自 2026-08-27 把规范落成参考实现的那一轮。
**每一条都是先出现症状、再定位、最后写成测试锁住的**，不是设想出来的。

**6.14 九个点作为派生手柄有用，作为存储是冗余的。**
`Draw.cs` 9 个点和 `Width/Height/Rad/Center` 并存 = 两个真相来源，
所以 9 个拖拽分支末尾各有十来行手工同步代码，是那个文件里最像的重复段。
而且 `Polygon[0]`（旋转手柄）是**屏幕尺度量却存在图像坐标里**，缩放时必须补算
（`OnMouseWheel` 里确实补了一行，漏了就是"缩放后手柄跑进框里"）。
唯一让 9 点不可替代的情况是"允许拖成一般四边形"，而 `Draw.cs` 每次都重新推成正经矩形。
**结论**：存 `(cx,cy,w,h,rad)`，手柄推出来。

**6.15 旋转手柄画在 `rad-π/2` 上，反推角度就必须 `+π/2`。**
漏掉的症状是"一抓住旋转点，图元当场跳 90°，之后拖的方向和转的方向一直错开"。
锁它的测试：*拖到哪个方向，手柄就跟到那个方向*（对每种有旋转手柄的类型跑一遍）。

**6.16 旋转中心必须用顶点质心，不能用外接框中心。**
不对称多边形一转，外接框自己就变了、中心跟着跑，于是每帧绕的都是不同的点——
表现为手柄漂、转一圈回不到原位。质心在旋转下不变。
**这个 bug 用对称样本测不出来**：矩形的外接框中心怎么转都不动，会蒙混过关（见 6.26）。

**6.17 手柄伸出距离要在图元自己的局部坐标系里算。**
直接量当前坐标，这个距离会随旋转变化，手柄一边转一边伸缩——那也是一种"偏移"。
做法：先把顶点按 `-rad` 转回去，再量"往上能伸多远"。

**6.18 旋转手柄必须落在轮廓外，还要有连接线和专门的图例。**
"从中心沿上方伸 25 屏幕像素"这种算法，框一大就落进框里，和顶点手柄挤在一起。
正确做法：从**轮廓在那个方向上的边界**再往外伸一个臂长。
伸出距离也别用"外接框长边的一半"——细长图元会把手柄甩到别的图元上面，
要按方向投影算。图例用带箭头的圆弧，不要用和顶点手柄一样的圆点。

**6.19 指针捕获和事件监听必须在同一个元素上。**
踩过：捕获在外层视口、监听挂在里层被 transform 的画布上。捕获会把事件**重定向**
到视口、不再往子元素派发，`pointerup` 于是永远收不到——草稿跨了好几个工具才被收尾，
画出来的东西横跨半张图。症状像"工具串味"，其实是这两层不一致。

**6.20 React 的 setState updater 必须是纯函数，别在里面调另一个 setState。**
踩过：`setScale` 的 updater 里调 `setPan` 做缩放锚点补偿，StrictMode 双调 updater，
补偿被算了两次——"放大之后光标下的东西跑了"，而缩放倍数看着完全正常。
缩放和平移要合成一个状态、一个 updater。同理，一个事件里别调两次 `setEdit`，
后一次会拿旧对象把前一次盖掉。

**6.21 SVG 里的文字是可选文本，会被浏览器拖走。**
在画布上拖动被当成"拖一段文字"，松手时新开一个搜索标签页——人只是想挪个框，页面跳走了。
只给 `<img>` 加 `draggable=false` 不够，整块画布都要 `user-select:none` +
`-webkit-user-drag:none` + 拦 `dragstart`。

**6.22 同一个图元内不许有两个手柄重合。**
弧卡尺在默认张角 90° 时，半径手柄曾经和弧终点手柄叠在同一点，其中一个永远点不中。
这种 bug 只在特定参数下现形，靠人点是碰运气；写成"任意两手柄距离 > 0"的性质测试才稳。
顺带一条：**卡尺的"起始角"手柄和"整体旋转"手柄是两回事**——前者标"从哪儿开始排窗"，
必须贴在骨架上，不适用 6.18。角色要分开命名。

**6.23 一次手势 = 一步撤销。**
拖一个手柄一秒发几十次变更，每次进栈的话人按十下 Ctrl+Z 才退回拖之前，撤销就废了。
做法：变更分 `step`（手势第一次，压栈）和 `amend`（后续，只换当前值）。
撤销只管标注列表，**不管缩放平移，也不管标定/备注这类表单输入**——
撤销一次"改标定"很怪，人期待的是"把我刚拖的那下退回去"。
换项目必须重置历史栈，否则撤销会把上一个项目的标注贴到这个项目上。

**6.24 多选只给整体挪和整体转，不给改形状。**
多个图元各有各的手柄，摆在一起没法说清"拖这个手柄改的是谁"。改形状必须先单选。
整体转要绕**群组中心**，各转各的中心是原地打转、相对位置纹丝不动。
框选用**相交即选中**，不要求完全包含——工业图上标注常互相压着、顶着图像边缘。
群组旋转手柄转起来之后要**锚在手势的起始中心和起始半径**上，
跟着当前外接框算会一边转一边漂（同 6.16）。

**6.25 顺手挪和进编辑态是两种手势，要分开。**
直接拖一个没选中的图元 = 顺手推一下，**挪完自动收工**，过程中不冒手柄；
先点选中再拖 = 打算继续调，挪完保持选中。
实现要点：按下时**先不选中**，起一次 transient 编辑，**松手时再定夺**——
真挪动了就收工，没挪动就是一次普通点击、选中它。

**6.26 对称样本测不出旋转中心的漂移。**
6.16 那个 bug 第一版测试没抓到，因为样本是矩形。
**几何类的性质测试要专门准备不对称、非凸、退化的样本**，
"看起来能过"的样本正是最容易放过 bug 的那种。
同类的还有：手柄重合只在特定参数下出现（6.22）、坐标在拖拽过程中是浮点（解析要认小数和负号）。

**6.27 自动保存的四条守则。**
① 防抖（改完停手 800ms 再写），拖拽途中不写盘；
② **失败时不清"已保存"标记**——清了会显示"已保存"而磁盘上没有，人下次打开才发现丢了，
这是最坏的失败方式；
③ 初次加载完成之前不写，否则会拿空规格盖掉磁盘上的好数据；
④ 同一时刻只有一个请求在飞、后来的排队，且切项目/关页面前把没落的那次补上，
**用当时那个项目 id**——不然防抖窗口里切了项目，数据会写到新项目头上。

以下 6.28–6.30 来自 2026-08-31 把规范落到第二个渲染库（Avalonia）的那一轮。
**三条都是"照规范抄的人会踩的坑"**——写规范的人知道，抄的人不一定。

**6.28 6.22 那条会被原样再犯一次，而且只有性质测试抓得住。**
照规范实现圆卡尺时，半径手柄被放在**固定的角 0**，而起始角恰好 0° 时它与起始角手柄
叠在同一点——正是 6.22 描述的那个 bug，换了个类型重演。
抓住它的不是人点，是那条"任意两手柄距离 > 0"的性质测试**扫参数**
（段数 × 张角 × 起始角 × 搜索长度，6×4×5 组）。
⇒ 规范里凡是"手柄坐在某个固定角/固定位置"的写法，抄的时候都要过一遍那条性质测试；
半径手柄应当**相对起始角固定错开**（跟着骨架转），不要挂在绝对角上。

**6.29 验"转一圈回原位"时，起算方向必须是手柄自己所在的方向。**
旋转手柄画在 `rad-π/2` 上（6.15），所以按 0° 起算去转 12 次 30°，
实际转的是 **90° + 360°**，判据当场变红——**而红的是判据，不是代码**。
这条与 6.15 是同一件事的两面：一面是实现要 `+π/2`，另一面是**测试也要**。

**6.30 没有逐帧取整的实现里，"逐帧累加 vs 起始快照"要靠夹取才能量出来。**
6.4 说的漂移来自"每帧取整"。而在全程用浮点、不取整的实现里，
两种写法**在数学上等价**——把画布改成逐帧累加，第一版判据照样绿（变异检查抓到判据不行）。
真正把两者分开的是**夹取的非线性**：宽高有 `max(1, …)` 兜底，
把一个角拖过对角（宽被夹到 1）再拖回来，累加实现里尺寸是从 1 开始长的，
**形状被永久吃掉一块**，而人只是手抖着拖过去又拖回来。
⇒ 判据写成"**拖过头再拖回来，形状回到原样**"。这条对所有带夹取的字段都成立
（半径、窗高、窗宽、段数）。

## §7 编辑器级功能（不属于单个图元）

### 7.1 多选

| 操作 | 规则 |
|---|---|
| 加减选 | Ctrl/Shift + 点击（画布上和清单里一致） |
| 框选 | 空白处拖；**相交即选中** |
| 框太小 | 当成"点了下空白"，不是框选 |
| 能做什么 | **只有整体挪、整体转、删除、复制**；改形状必须先单选（6.24） |
| 整体转 | 绕群组外接框中心；手柄锚在手势起始中心与半径上 |

### 7.2 撤销重做

| 项 | 定值 |
|---|---|
| 粒度 | 一次手势 = 一步（6.23） |
| 范围 | 只管标注列表；不管视图、不管表单 |
| 栈深 | 50 |
| 快捷键 | Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y |
| 换数据源 | 必须重置 |

**快捷键必须在焦点位于输入框时全部让路**，否则在名称框里按退格会删掉图元——
这种"改个名字标注没了"的事故，人第一反应绝不会怀疑到快捷键头上。

### 7.3 精确数值编辑

拖拽定不出整数。工业标注要的是"正好 90°""半径正好 50"，手拖永远是 89.7°，
而这个数会原样进规格书交给下游。**每种轮廓都要能直接填数。**

做法：把"哪些数能填"做成一张表（`numFields(shape)` / `setNumField(shape, key, value)`），
界面照着渲染，不用为 13 种各写一遍表单。

- **角度对外一律用度、对内一律存弧度**，转换只在这一层做
- **越界值夹回合法范围，不要原样收下**：半径填 0 会让图元消失、
  窗数填十万会把页面卡死，而人往往只是手滑多按了个零
- 填非数（空框、乱敲）原样返回，别产生 NaN 图元
- 多边形/掩膜不给数值表——顶点太多，一个个填没意义

### 7.4 文字

文字的命中框**必须靠渲染层量**（SVG `getBBox()` / Canvas `measureText()`），
不能按字符数估：中文约 1em、ASCII 约 0.5em，估算值对两边都错，结果是点不中。
文字内容要可编辑；清空时退化成占位符，别让图元变成看不见也点不中的东西。

## §8 当前状态与欠账

**已固定并有实现验证**（2026-08-27）：13 种类型的数据模型、五态状态机、命中优先级、
四个屏幕空间常量、旋转矩形的三种拖拽不变量、卡尺四参数模型、画布导航、

参考实现分四层，换渲染库时**只有最后一层要重写**：

```
packages/shared/src/annot/     纯函数，无渲染无事件，233 条单测
  types      13 种轮廓的模型、屏幕空间常量

  hit        命中判定（不依赖渲染库）
  handles    手柄布局与拖拽
  draft      绘制手势的状态转移
  group      多选与群组操作
  history    撤销重做
  fields     精确数值编辑
apps/web/src/components/
  ShapeCanvas.tsx   指针/键盘事件 -> 上面那些纯函数；缩放平移；文字度量
  ShapeView.tsx     13 种的 SVG 画法
```

**验证方式**（换机器后照这个跑；条数为 2026-08-27 实测）：

|---|---|

两层缺一不可：几何 bug 靠单测，"手柄点不中""拖出标签页""缩放后跑偏"这类只有真浏览器测得出来。
