# 判据绿着，却什么都没验

> 起于 2026-09-21。这份和本库其他文档不一样：**它管的不是代码，是判据本身。**

一条判据有三种状态：**红**、**绿**、以及**绿着但什么都没验**。

第三种最贵。它占着"这一块验过了"的位置，而它挡不住任何东西。它比没有判据更坏——
没有判据时人还知道这儿是空的。

这份清单收的全是**真的发生过**的：某条判据写完是绿的，事后发现它对着错误的实现<b>照样绿</b>。
每一条都带：**怎么写会空、怎么发现的、怎么写才不空**。

**一句话版本**：判据要能回答"**如果实现写错了，我会红吗**"。回答不了就先别写。

## §1 反证：断"错误的写法必须红"

### 1.1 形状

同一条用例里跑两遍：**正确的写法要绿，错误的写法必须红**，失败信息直接写

> 「这条判据分不开两种写法，白写了」

不写反证的话，判据可能对**两种写法都绿**，而你要等到下一次变异检查才知道——
变异检查不是每次都跑，判据是每次都跑的。

### 1.2 它当场救回来的几条（都是 2026-09-21 一天之内）

**① 「从来不画」的实现照样绿。**
19 个算子有 12 个显示开关。判据写的是"关掉之后那一类图元一个都没有"——
而一个**从来不画**的实现同样满足它。加上"开着⇒必须有"那半边之后，
变异检查专门把某一处改成 `if (false && …)`，4 条红，其中就有这一条。

**② 三个词的码位顺序碰巧和声明顺序一致。**
参数分组要"按声明顺序"而不是"按字母序"。判据原本用「找边/拟合/显示」，
而这三个词的 UTF-16 码位顺序**恰好**等于声明顺序 ⇒ 两种实现产出同一个结果。
反证当场红了，换成真算子实际的「拟合/显示/找边」才成立。

**③ 12 步均分一圈，把漂移抵消掉了。**
验"旋转中心用顶点质心而不是外接框中心"，样本特意选了不对称非凸的 L 形，
断"转 12 次 30° 回到原位"——绿。**把支点换成外接框中心，还是绿**（漂移 < 0.01 px）：
每一步漂的那点位移自己抵消了。
真正分得开的是**转的过程当中**：绕质心转质心不动，绕外接框中心转质心会被甩出去。
⇒ 断**一步之后**的质心，不是转完一圈之后的顶点。

### 1.3 反证要断"不一样"，不要断"错成什么样"

断具体的错误值等于把错误实现的行为也固化进判据，底层一改就连带红一片。
断 `Assert.NotEqual(正确, 错误路径的结果)` 就够。

## §2 样本本身让 bug 消失

判据是绿的，可能只是因为**这一组样本碰巧测不出来**。

| 样本的毛病 | 漏掉的那一整类 |
|---|---|
| **对称** | 矩形的外接框中心怎么转都不动 ⇒ 旋转中心写错了也看不出来 |
| **正方形的图** | 等比缩放补边时正方形的补边恒为 0 ⇒ "忘了减补边"这一整类不存在。必须扫长宽比（16:9、竖图、细长条） |
| **拿默认值当值** | "读了配置"和"用了默认值"分不开 ⇒ 一个根本不读配置的实现照样绿 |
| **图比控件小** | "图比控件大"那一整类布局问题在测试里根本不存在（现场一张 1920×600 的照片才暴露） |
| **两点共线 / 退化** | `[1,2,2,2]` 配 2 类时通道优先和通道最后都说得通，代码（正确地）拒绝推断，而判据以为它坏了 |

⚠ **样本不对称是必要条件，不是充分条件**（见 §1.2③）：样本对了，**步长序列**还可能把 bug 抵消掉。

## §3 "有东西"不等于"对"

### 3.1 断存在 vs 断坐标

叠加图（画在图像上的那些线、十字、框）最容易写空：

```csharp
Assert.Contains(overlays, o => o.Kind == OverlayKind.Polyline);   // 画到哪儿都绿
```

**画到别的坐标时，"有一条线"照样成立。** 要断的是坐标本身：
那条线的两个端点**落在拟合出来的那条直线上**（点到无限长直线的距离，给个明确容差）。

同理：找点的十字**就是** `point` 端口交出去的那个坐标；判定框的四个角**就是**缺陷的外接框。

### 3.2 只断对象图 ⇒ "挂上了"和"点得动"是两回事

无头界面判据里关掉渲染（`UseHeadlessDrawing = true`）时，几何查询一律返回 false，
于是"点在这个按钮上算不算命中"**根本问不出来**，只能退回去断对象图。
而对象图绿了只说明控件挂上了。

⇒ 无头会话要开 Skia + 字体，**真的模拟鼠标和键盘**。
（HuikeAgent 2026-08-21：右键菜单缺陷连修三轮都只断了对象图，真的模拟一次右键，第一次就现形。）

### 3.3 自绘控件的 `Render` 抛异常时，多数框架只是把那块画空

不炸、不报错、不写日志。只断对象图的判据全绿，而屏上一片空白。
⇒ 每个自绘页面至少一条判据**真的光栅一帧**。

### 3.4 "绿了"和"看着对"是两回事

**这条是这一天最贵的一课。**

某个版本 621 条判据全绿，把软件四个页签各截了一张图人看一眼，当场发现**五个问题**：

- 中间那一列被工具集按钮吃光，**这一页的正事（工具表）一行都看不见**
- 参数面板一直空着——代码里先选中第一行触发填充，**紧接着又把它清空了**
- 提示文本里写了 markdown 的 `**`，而控件显示纯文本，屏上就是两个星号
- 同一个数在屏上有两处，而其中一处永远是空的
- 工具集里三个一模一样的「找圆」，人只能靠位置猜

**这五个没有一个会被判据抓到**，因为它们全是"摆得对不对"，而判据验的是"算得对不对"。

⇒ 判据里顺手把渲染出来的帧存成 PNG。存下来就是给人看的，
"绿了"这件事回答不了"摆得好不好看、字有没有挤在一起、人第一眼会不会看错"。

## §4 变异检查：怎么知道这批判据管不管用

**做法**：把实现改坏一处 → 跑全量 → 确认**红的正是该红的那条、别的不动** → 还原。

⚠ 还原要**逐字节校验**（sha256），别靠"我记得改回去了"。
未入库的文件尤其危险——git 不知道它原来长什么样，变异会叠加。

**频率**：这一天四批判据分别做了 5、6、9、5 次。经验是**每写完一组就做一轮**，
而不是攒到最后——攒到最后时"该红的没红"已经分不清是哪一条判据的问题。

**要记的两件事**：

1. **"不该红的跟着红"也是信号**。改「引导跳过没找到的工位」时另一条判据也红了，
   查下来是同一个缺陷的两个面——那是对的。而如果跟着红的那条和被改的地方
   **没有因果关系**，说明它断得太宽。
2. 变异检查发现的是"判据不行"，**而反证（§1）是把这件事固化进判据**。
   前者偶尔跑，后者每次跑。

## §5 断言本身的坑

### 5.1 `Assert.Equal(expected, actual, decimals)` 是"各自四舍五入再比"

不是"差值小于 10⁻ⁿ"。`Assert.Equal(9.75, 9.747, 1)`：9.75 进位到 **9.8**、9.747 退到 **9.7** ⇒ **红**，
而两者只差 0.003。⇒ 断误差本身：`Assert.InRange(Math.Abs(actual - expected), 0, 0.01)`。

### 5.2 断类型，不能只断值

`cond ? long : double` 的类型是 `double`（见 [静默改值](../engineering/silent-value-corruption.md) §1.1），
于是整数那一支等于没写。而判据报的是

```
Expected: 12
Actual:   12
```

**两边打印出来一模一样。** ⇒ `Assert.IsType<int>(boxed)`。

同类：`null` 和空串经 `?.ToString()` 一过，在屏幕上和在 `Expected:/Actual:` 里都一样，
而下游行为完全不同（按类别分目录会变成 `NULL` 目录）。

### 5.3 恒真断言

```csharp
Assert.True(done.Executed || !done.Executed);   // 什么都没验
```

这是我自己写出来的。写它的时候的想法是"换不换型不是这条判据管的事"——
**那就不该写这一行**。真正该断的是"跑完之后这一侧的身份一个字没变"。

⚠ 一条用例里**每一行断言都要能回答"它防什么"**。答不上来的那一行删掉，
留着它只会让整条判据看起来比实际更有分量。

### 5.4 断了个寂寞：前提没验

断"条子上那个身份没被采信"之前，**先断条子上确实写着那个身份**。
不然前提要是空的，后面那两条断了个寂寞。

## §6 共用的判据家伙：手抄一定会分叉

无头会话的配置（开不开 Skia、带不带字体、挂不挂真实的根）在三个测试工程里各有一份，
**其中两份的注释里明写着「照 X 那一份搭，口径必须一样」**——
也就是说大家都知道必须一样，而维持一样的办法是人每次记得同步。
实测三份的 md5 互不相同（引用的主题工程都已经不是同一个了）。

**口径不一样的后果不是编译错**：同一个控件在几个工程里会有几种表现，
而每一边的判据**各自都是绿的**。

⇒ 抽成一个共用库。两个技术细节值得记：

1. **xUnit 的 `[CollectionDefinition]` 是按程序集认的**，抽到共用库里对各测试工程一律无效，
   而无效的表现是**用例照跑、fixture 却没被建起来**，空引用炸在一个毫不相干的地方。
   ⇒ 会话本身抽走，那三行留在各家。
2. 共用库**不是测试工程**（`IsTestProject=false`），要引 `xunit.v3.extensibility.core` 而不是
   `xunit.v3`——后者会强制 `OutputType=Exe`。xUnit 自己会把这句话报出来。

## §7 当前状态与欠账

**这份清单收的都是真的发生过的。** 想加"应该注意 X"时，先问自己：
我见过哪一条判据因为这个而空绿了？答不上来就别加——那是最佳实践清单，不是这个。

**还没形成做法的**：

- 怎么在 CI 上**常态化**变异检查（现在是人手动做，一组判据一轮）
- "截图给人看"这一步怎么不变成走过场（现在是存 PNG，靠人主动看）
