09-08 那一轮的：root 跑出来的绿是假绿（权限类缺陷只在非 root 才现形，Linux 回归账号从此改成非 root）、两种失败的异常类型相同而下一步相反（靠"我改不改得动它"分开，别靠异常类型）、Windows 上是一个目录而 Linux 上是两个（`Config/` 大小写，且修法里的路径比较也要按平台选）、功能做了一半而缺的那半没有落点（`IsDesignTime: false` 只在判据里出现过——这类事实可以 grep）、无头 UI 一轮收尾会执行还排着的渲染作业（队列没排干时症状落在下一条判据上）、模态确认框在无头下开不了所以"问那一句"要留接缝（外加：关 owner 窗口时从属窗口的关闭请求先到）、以及置灰理由挂在每次发布上会让理由里那个探针变成持续的文件写**；**4.89–4.91 是同一轮收尾的：变异检查还原后编译系统要看得见（`copy2` 保留 mtime ⇒ 复跑的还是变异那次的 dll，而"改回去了还是坏的"最像产品真坏了）、PowerShell 脚本参数不能叫 `$Args`（分支静默不走，症状和"命令行开关没生效"这个产品缺陷一模一样）、以及一个改变"下次打开看到什么"的开关必须同一轮给出回来的路（屏幕留痕 + 设上就说怎么回来 + 界面里那条路 + 命令行逃生口；四档里"目录不在了"刻意不进）**；**4.92–4.93 是那一轮收尾又撞的两条：默认内容的含义会随功能变化（"第一次装机的样板"在有了工程管理之后变成"每建一个工程都撞一次"，而且删它要整份删——留着会被下一个人接回启动路径），以及 `await using` 自己也是一次 await（库里少这一处 `ConfigureAwait(false)`，界面线程上阻塞等它就是死锁，而症状是"测试跑不完"、最像环境慢）** ；**4.94–4.100 是 09-08 第三轮（补屏控件 + 出 Linux 交付包）的：接口上"带默认实现的属性"被实现成同名方法时编译器不吭声、功能静默失效，而判据用具体类型调那个方法所以照样绿（判据和产品走的不是同一条路）；一句对的约束得出了偷懒的结论（"控件要在调度线程上造"⇒"那就不造控件"，代价是 `Create()` 从没被执行过）；相对路径按进程当前目录解而人可以从任何目录起软件；跨平台交付时"同名不同内容"的缓存不能跟着走（名字里带的是显卡型号、不带平台，所以名字不会提醒任何人，而后果是硬崩）；交付包里的路径要占位符 + 安装时替换 + **记下当时的根**（包被移动过要重新指并说出来）；判据里的全称量词必须说清论域（指到解开的安装包上跑时，"一个都没被跳过"会红在装载器做对了事上）；WSL 里连续启界面必须有同会话对照**；**4.101–4.105 是 09-08 第三轮（照现场那份 51 个模块搭流程）的："模块少了很多"少的不是插件而是流程——随手搭的示范流程和照现场搭的那份在交付包里长得一模一样（同样在、同样编得过、屏上同样有数字在动、验收同样全绿），所以验收要加**形状**判据而不只是"东西在不在"；一条产线六台相机时六个取图节点会**全部拿到同一帧**而每个节点都报"完成"（判据要断"两路各自拿到了自己那张"，断"跑完了"证明不了）；脚本"报了成功"而软件行为没变（同一个脚本连错两次：改错了字段、以及 ISO 时间串截到整秒后字符串序≠时间序）；环境自检里问硬件的命令一律带超时（D 态的 `nvidia-smi` 让安装脚本永远不返回，而"超时了"和"没装驱动"的下一步不同）；PowerShell 5.1 读没有 BOM 的 `.ps1` 按 ANSI 解时**脚本行为会静默改变**，不止是中文乱码**；**4.106–4.110 是 09-09 那一轮（窗口暗色 + 节拍）的：跨平台修复只在一个平台验过时，另一个平台上它常常不是"没生效"而是**把问题变成两倍**（判据断的是"我们提了这个要求"，不是"系统答应了"——两个平台都绿）；计算属性不发变更通知会让绑定永远停在初值，而"算出来了"的判据绿着、同一块界面里另一半在动是最强的伪装；`??=` 用在有样式默认值的属性上是一句静默空操作；"看起来天经地义"的不等式判据可能是假的，真流程上断不出来的东西要用手造输入断；`pkill -f` 会连执行它的那个 shell 自己一起杀掉，后面的拷贝一行都不执行**；**4.111：一个数字回答不了"慢在哪"，两个对不上的数字能（整机节拍 1520 ms vs 每路 72~77 ms，差的 1400 ms 一眼看出不在检测里）——外加两条：`foreach + await` 遍历互相独立的外部设备时默认它是错的（代价随设备数线性增长，一两路的开发环境里不显形），以及"为了让人看清"而加的等待不许进性能读数**；**4.112–4.118 是 09-09 下半场（条件分支改成选父节点的属性）的：`timeout` 挡不住 D 态进程——上一轮"已修好"的那个超时在同一处又卡了十分钟（一个修复只验过它想挡的那类里较容易的一半时，长得和真修好了一模一样）；"测试绿了"可能是上一次的二进制在绿，而做掉信号的是我为了少看点输出加的那个 `grep`；检查方法自己会坏且**给出相反的结论**（机器上没装 `strings` ⇒ `grep -c` 恒为 0，差点宣布改动没进去）；同一个缺陷形状在第二处重演——"什么时候算改了"是每个实现各自决定一次的语义，判据必须跟着实现走；拆/拼互为逆时"拆不动"必须返回空而不是半张表（`(A`、`2)` 那种名字看起来像拆成功了）；两类插件够不着彼此时共用的语法必须搬到唯一共同依赖上，抄一份的失败方式是"编辑器拼出一句算子看不懂的话而屏幕上完全正常"；以及给人挑的清单在异步 DAG 上"用不了"是**偶发**的（非祖先节点这一帧可能没跑完，得同时加一条只定先后的边）**；**4.119–4.126 是 09-10 下半天到 09-11（分支拆三口 / 模块改名 / 深度学习收口）的：**过度断言也要实测**——一个对的结论配了个错的证据（拿 md5 差异当"实测佐证"，而 MSVC 同源连编两次哈希就不同），比"做不到"那一种更难自查，因为**结论对的时候没人回头看证据**；`git commit` 提交的是**索引**而索引也是共用的（只 add 自己三个文件照样带走别人两个，`git status` 看不出来，根治是 `commit -- <路径>`）；"本地全绿"可能是**工作区绿**不是 HEAD 绿（main 编不过一整天、CI 连红六条，而编译断在插件那步⇒测试步骤一次都没跑）；干净检出验 HEAD 是**三步**（少编原生核心会红 70 条 + 耗时 40 秒→4 分，那是它的指纹）；同一件事有两份表示时**藏起来的那一份才是成本**（右键标支路 vs 三个出口，加新的和删旧的必须同一轮）；机制归主干道时让**声明**跨过边界而不是让内核认识领域（`BranchResult` / `ReferencesNodeNames`，且要用 init 属性不能加位置参数）；迁移机制先于需要建起来、第一次用上只写那一段（两步刻意一个按端口名认一个按算子键认）；把一个量从端口搬走时**判据要跟着搬家、一条都不能少断**；**4.127–4.130 是 09-11（判定条件改成旧慧可的「组」）的：产线判定别让人在脑子里算优先级——一行「A 且 B 或 C」表达能力更强却更容易配错（错的表现是"这一路偶尔判反"、每条轨迹看起来都正常），两层分组把层次摆到看得见；算子往黑板上挂的量**声明出来**才有人问得到（类别只剩黑板那一份之后，条件式跑得好好的而规则表里那一行是空的——运行期有、编辑期没有，是 4.118「列出来的一定引用得到」的反方向）；界面上按控件在树里的位置取值，**布局一改就炸**且炸点离改动很远（外加一个不报错的坑：窄栏里横向 StackPanel 不换行不报错，只是把右边那个静静切掉）；以及 `Move-Item` 还原被变异过的源文件会把**旧时间戳**一起搬回来，于是「0 个错误」的编译其实什么都没做；**4.131–4.134 是 09-11 下半天（左下角耗时 + 按类别设阈值）的：变异检查在**真实数据**上可能分不开两个字段（跑两帧时「最近/最大/最小」是同一个数，把 LastMs 换成 MinMs 判据照样绿）⇒ 把格式化摘成纯函数喂各不相同的数，同时保留真产线那条（一条量说了什么、一条量取的是哪一份）；统一那套 JSON 选项的 `DictionaryKeyPolicy` 会改**人取的名字**（「OD超规」→「oD超规」，只有首字母是大写 ASCII 的类别才发作）；数值框里「留空」和「填 0」是两个意思而空格子自己说不出来 ⇒ 水印写出留空等于多少；以及一个数算出来了、模型读得到、还不止一处有，而**没有一处在人所在的那一页**；**4.135–4.138 是 09-11 收尾（深度学习改成只过滤）的：新旧格式**键对得上、字段全不一样**时 JSON 静默忽略未知字段会把旧内容解成"什么都不做"（空规则组 = 不过滤 = 悄悄放行），要开 ## 怎么维护

在**任意项目目录**下对 Claude Code 说 `/update-experience`，它会：

1. 读取本仓库 `docs/` 下所有文档的 front matter，找出与当前项目关联的那份；
2. 扫描该项目自 `last_updated` 以来的变化（git log、未提交改动、新增测试与回归结果）；
